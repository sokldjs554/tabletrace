## 비교 항목별 관찰

### 문서와 표를 탐색하는 방식
- OCR Form Tools: **왼쪽 세로 썸네일 목록 → 가운데 큰 문서 뷰어 → 오른쪽 태그 패널**의 3단. 문서 전환은 왼쪽 목록 클릭, 표는 문서 위에 격자 오버레이로 표시되고 표 아이콘으로 표 모드 진입.
- Tabula: 문서 페이지 위에 영역을 끌어 표를 선택, 추출 결과를 표로 미리보기 후 내보내기.
- Document AI Workbench(텍스트): 문서를 가져와 스키마(필드) 정의 → 라벨 → 학습 → 평가 단계가 좌측 내비게이션에 고정.

### 질문·검색과 결과를 보여주는 방식
- promptfoo: 결과를 **표**로 — 행은 입력, 열은 모델/프롬프트, 셀 안에 PASS/FAIL 배지와 출력. 상단에 통과율·토큰·지연 요약, 필터 칩(All/Failures/Passes/Errors).
- MLflow 트레이스: 왼쪽에 호출 트리(스팬 이름·소요), 오른쪽에 선택 스팬의 입력/출력/속성 탭.

### 원문·셀·답변 근거를 연결하는 방식
- OCR Form Tools: 문서 위 값에 **색 테두리**, 오른쪽 태그 패널의 같은 색 라벨에 값·신뢰도. 즉 "문서 위 하이라이트 ↔ 오른쪽 필드"가 색으로 짝지어짐.
- Analyze 화면: 예측값 옆 **신뢰도(%)**와 페이지 번호 배지(P.1).

### 작업 상태와 오류를 보여주는 방식
- OCR Form Tools 하단 상태 바(저장소, 태그 수, 문서 수, 버전), 상단 "Run OCR on all files" 같은 긴 작업 버튼.
- MLflow 대시보드: 요청 수·지연 p50/p90/p99·오류율을 작은 카드로.
- promptfoo: 셀 단위 PASS/FAIL, 실패만 필터.

### 많은 정보를 한 화면에 배치하는 방식
- 3단(목록 / 본문 / 속성)이 공통. 오른쪽 패널은 접을 수 있는 섹션. 수치는 카드(제목·큰 숫자·보조 설명).

### 처음 들어온 사용자가 이해하는 흐름
- Document AI 제품 페이지: 제품 정의 한 문장 → "Try Workbench" → 기능 카드 → 튜토리얼 목록(가져오기/라벨/학습/평가).
- Label Studio: 템플릿 그리드로 "무엇을 할 수 있는지"를 먼저 보여 줌.

## 데모 배경 조사 — 다른 제품은 어떻게 만들었나

"데모 배경"을 **데모 화면의 바탕(캔버스)과 그 위에 놓이는 장면**으로 해석했다. 사용자가 금지한 것은 AI가 흔히 만드는 장식용 배경(보라·파랑 그라데이션, 빛 번짐 원, 유리 효과, 점·격자 질감, 떠다니는 도형, 그라데이션 글자의 대형 히어로)이다. 다른 제품은 바탕을 어떻게 만드는지, 공개 저장소의 화면 7장을 새로 받아(`raw.githubusercontent.com`) 바탕 색을 PIL로 표본 측정했고, 그중 4장(OCR Form Tools 라벨링, MLflow 트레이스, promptfoo 결과, doccano 프레임)은 이미지를 직접 열어 눈으로 확인했다. 표의 "확인 방식"에 구분해 적었다. 다른 해석(예: 데모 장면 구성)이 의도였다면 알려 달라.

| 제품 | 화면(확인 방식) | 관찰한 바탕 처리 | 측정값 | 장식 |
|---|---|---|---|---|
| Microsoft OCR Form Tools | `docs/images/apply-labels.png` (눈으로 확인 + 측정) | 어두운 단색 앱 셸. 가운데 문서 뷰어는 **문서 페이지(흰색)를 거의 검은 중립 캔버스 위에 놓는 레터박스**. 썸네일도 같은 검은 레터박스. 하단 상태줄만 파란 단색 | 셸 `#474b4f`, 패널 `#303038`, 캔버스 `#182020`대, 상태줄 `#136691` | 없음. 그라데이션·질감·그림자 없음 |

확인하지 못한 것: Label Studio(이미지 403), Streamlit(404), Gradio(이미지가 Hugging Face 호스트라 차단), Datasette(README에 화면 이미지 없음). 이들은 "조사했다"고 쓰지 않는다.

**공통 패턴 (눈으로 확인한 4장과 색을 측정한 3장에 한해, 표본이 작다)**

1. 바탕은 **단색 중립면**(흰색·옅은 회색 또는 어두운 회색)이다. 그라데이션·이미지·질감·블러를 쓴 제품 화면은 눈으로 확인한 4장에서 없었다(측정만 한 3장은 색 분포가 단색 중심이라는 것만 확인).
2. 시각적 흥미는 바탕이 아니라 **실제 콘텐츠**(문서 페이지, 표, 트레이스 트리, 결과 표)가 만든다. 문서 도구는 문서 페이지를 어두운 중립 캔버스에 올려 페이지를 돋보이게 한다.
3. 색은 **상태와 근거**(태그 색, PASS/FAIL 배지, 선택 행, 차트 계열)에만 쓴다.
4. 영역은 그림자가 아니라 **1px 선과 한두 단계의 회색 차이**로 나눈다. 그림자·둥근 틀은 README 캡처를 꾸밀 때만 보였다.
5. 시나리오 이름은 장식 없는 **텍스트 라벨**이다.

**금지한 것과 이유**

| 금지 | 이유 |
|---|---|
| 보라·파랑 그라데이션, 메시·오로라 배경, 빛 번짐(radial) 원 | 확인한 어떤 제품에도 없고, 근거 셀 하이라이트(노랑)와 상태색을 구분하기 어렵게 함 |
| 유리 효과(backdrop blur), 반투명 카드 | 표 글자의 대비를 떨어뜨림. 읽기가 일인 화면에 부적합 |
| 점·격자·노이즈 질감, 떠다니는 도형·파티클·움직이는 배경 | 표의 격자선과 시각적으로 충돌하고 주의를 분산 |
| 그라데이션 글자 히어로, 이모지 아이콘 | 제품이 아니라 랜딩 페이지의 인상을 줌 |

**TableTrace의 바탕**

- 전체 바탕은 단색 `#f5f6f8`, 패널은 흰색 `#ffffff`, 구분은 1px 선 `#d9dee5`(`console/styles.css`의 `--bg`, `--panel`, `--line`).
- "장면"은 만든 배경이 아니라 **실제 문서**다: 한국어는 KorWikiTQ의 실제 위키 표, 영어는 OpenStax Chemistry 2e의 실제 교과서 표(출처·라이선스를 각 화면에 표시). 지어낸 시나리오를 바탕처럼 깔지 않았다.
- 색은 근거 노랑·상태색에만 쓴다. 움직이는 것은 로딩 표시(스피너, 스켈레톤)뿐이고 이것은 상태 표시다.
- 회귀 방지: `tests/test_console_style.py`가 CSS·HTML에서 `radial-gradient`, `conic-gradient`, `backdrop-filter`, `blur(`, `background-image`, `<canvas>`, 장식용 `<video>`를 찾으면 실패하고, `linear-gradient`는 로딩 스켈레톤에만 허용한다.

## TableTrace에 반영한 것

| 관찰 | 반영 |
|---|---|
| 3단 구조(목록·문서·속성) | 왼쪽 문서/표 목록, 가운데 본문+표 뷰어, 오른쪽 질문·답변·검토 패널. 모바일은 탭으로 전환 |
| 문서 위 하이라이트 ↔ 오른쪽 필드의 색 짝짓기 | 근거 셀에 테두리+번호 배지, 오른쪽 근거 목록의 같은 번호를 클릭하면 해당 셀로 스크롤·강조. 본문 근거는 문장 하이라이트 |
| 예측값 옆 신뢰도·페이지 배지 | 답변 옆에 **검증 결과**(통과한 검사 수, 보류 사유)와 셀 좌표(r/c) 배지. 모델 확률 대신 검증기 판정을 보여 줌(모델 신뢰도는 과신 유발) |
| 긴 작업의 상태 바 | 질문 제출 후 `대기→실행 중(경과 ms)→완료/보류/오류/시간 초과` 상태 띠, 작업 ID |
| 트레이스 트리 + 상세 탭 | 결과 아래 "실행 추적": retrieve → propose → tool → verify 단계와 소요 ms, 각 단계 입력/출력 펼치기 |
| 결과 표 + PASS/FAIL 배지 + 조건 요약 | 연구 결과 화면: 모델 비교·추론 최적화·병렬 실험을 표로, 각 표 위에 **실행 조건(하드웨어·데이터 크기·반복 수)** 고정 표시 |
| 튜토리얼식 첫 화면 | 첫 방문 시 "문서 선택 → 질문 → 검색·도구 실행 → 근거 검토" 4단계 안내 띠(닫기 가능), 각 문서에 대표 질문 칩 |
| 실시간/저장 결과 구분 | 상단 배지: `실시간 실행(백엔드 연결)` / `저장된 실행 결과(백엔드 없음)`; 저장 결과에는 기록 시각·모델·커밋을 표시 |
