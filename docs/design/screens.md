# 화면 구조와 주요 사용 흐름 (구현 전 설계)

## 화면 목록

1. **워크벤치** (`/`, 기본) — 문서 탐색 + 문서 보기 + 질문·검토
2. **연구 결과** (`/#research`) — 모델 비교, 강화학습, 추론 최적화, 멀티 GPU 실험 결과와 조건
3. **API 문서** (`/docs`, FastAPI 자동 문서; 실시간 모드에서만)

## 워크벤치 레이아웃

```
┌──────────────────────────────────────────────────────────────────────────┐
│ TableTrace  표·문서 근거 검증 워크벤치     [한국어 표|영어 화학]  ● 실시간 실행 │
│ 처음이세요? ① 문서 선택 → ② 질문 입력/대표 질문 → ③ 검색·도구 실행 → ④ 근거 검토  [닫기] │
├──────────────┬───────────────────────────────┬───────────────────────────┤
│ 문서 (검색)  │ 문서 제목 · 출처 · 라이선스     │ 질문                      │
│ ▸ 문서 A     │ 본문 문단 … (근거 문장 하이라이트) │ [입력창            ] [실행] │
│   표 1       │                               │ 플래너: 자동|신경망|휴리스틱 │
│ ▸ 문서 B     │ 표 1  (r/c 좌표, 단위)          │ 상태: 실행 중 · 1,240 ms   │
│   …          │  ┌──┬──┬──┐  근거 셀 ①②        │ ─────────────────────────│
│ 대표 질문     │  │  │  │  │                   │ 답변  1,062,201 명   [완료] │
│  · 셀 근거    │  └──┴──┴──┘                   │ 근거 ① r0c4 12,274,031 명 │
│  · 계산      │                               │      ② r1c4 11,211,830 명 │
│  · 본문+표   │                               │ 계산  12274031 − 11211830  │
│  · 단위·기간  │                               │ 검사  ✓ 셀 범위 ✓ 단위 ✓ … │
│  · 답 없음    │                               │ 추적  retrieve 3ms → …     │
```

- 데스크톱(≥ 1000px): 3열(260 / 가변 / 400). 가운데·오른쪽은 각각 독립 스크롤.
- 모바일(< 1000px): 상단 탭 `문서 | 질문·결과`. 표는 가로 스크롤 컨테이너.

## 주요 사용 흐름

1. 진입 → 코퍼스 선택(기본: 한국어 표) → 왼쪽 문서 목록에서 문서 클릭 → 가운데에 본문·표 표시.
2. 대표 질문 칩 클릭(또는 직접 입력 + Enter) → 오른쪽 상태 `대기 → 실행 중` → 완료.
3. 답변 카드: 상태(완료/보류/오류), 답변, 근거(셀 번호 배지 / 문장), 계산식(값·단위), 검사 목록, 실행 추적.
4. 근거 배지 클릭 → 가운데 표의 셀로 스크롤 + 강조. 본문 근거는 문장이 노란 배경.
5. 보류: "답변 보류" 배지 + 이유(문서에 없음 / 모호 / 단위 불일치 / 검증 실패 / 검색 실패) + 어떤 검사가 실패했는지.
6. 오류/시간 초과: 빨간 띠 + 재시도 버튼. 백엔드 없음: 입력창 비활성 + 저장된 결과 안내.

## 상태 설계

| 상태 | 표시 |
|---|---|
| 빈 상태(문서 미선택) | 가운데: "왼쪽에서 문서를 고르세요" + 코퍼스 설명; 오른쪽: 입력창 비활성 |
| 로딩(문서/목록) | 스켈레톤 줄 3개 |
| 실행 중 | 상태 띠 + 경과 시간 타이머(500 ms 간격) + 실행 버튼 비활성 |
| 완료(answered) | 초록 배지 "완료" |
| 보류(abstained) | 회색-주황 배지 "답변 보류" + 사유 |
| 오류/시간 초과/대기열 초과(429) | 빨간 띠 + 메시지 + 재시도 |
| 저장된 결과 | 파란 배지 "저장된 실행 결과 · 2026-10-29 · mt5-small-tabletrace · commit abc1234" |

## 접근성·키보드

- 문서 목록: `role=listbox`, ↑/↓ 이동, Enter 선택. 대표 질문 칩: 버튼. 입력창: Enter 실행, Shift+Enter 줄바꿈 없음(단일 행).
- 모든 상호작용 요소에 `:focus-visible` 윤곽. 색만으로 상태를 구분하지 않음(아이콘+텍스트).
- 표 셀 `title`에 좌표·헤더·단위.

## 시각 원칙

- 바탕 `#f5f6f8`, 글자 `#1d2733`, 강조 `#2b5c8a`, 근거 `#fff1c2`+`#c99a1a` 테두리, 보류 `#8a6d1f`, 오류 `#a4262c`.
- 그라데이션·글로우·장식 아이콘 없음. 시스템 글꼴. 숫자는 등폭 보조 글꼴.

## 2026-11-17 개편 뒤의 구조

위 내용은 구현 전의 설계다. 2026-11-17에 화면을 고쳤고 지금 구조는 다음과 같다(이유와 검사는 `docs/REPORT.md` §28).

| 화면 | 달라진 것 |
|---|---|
| 워크벤치 | 왼쪽: 문항 묶음(평가 파일 하나의 전체), 그 묶음의 문서, 그 문서의 질문과 판정. 오른쪽: 답과 정답, 같은 질문의 플래너 비교, 근거와 숫자로 읽은 값, 계산, 모델의 제안과 검증 결과를 나란히 놓은 표, 검증 항목, 실행 추적. 들어가면 결과 하나가 열려 있고 휴대폰은 결과 탭에서 시작한다 |
| 문항별 결과 (새 화면) | 한 묶음의 문항 전체와 플래너마다의 판정. 유형별로 맞은 수. 표시를 누르면 그 문항이 워크벤치에서 열린다 |
| 연구 결과 | 결론과 그림이 먼저, 실험 기록은 주제별로 접혀 있다 |
| 직접 실행해 보기 (정적 데모) | 질문 칸 아래의 접힌 상자. 실행 환경을 불러오면 저장된 제안을 바꿔 검증기에 넣거나 휴리스틱 플래너로 실행할 수 있다 |

표 위의 표시는 셋이다. 노란 바탕과 번호는 검증기가 확인한 근거 셀, 붉은 점선과 "모델"은 모델이 인용했지만 근거가 되지 못한 셀, 초록 점선과 "정답"은 정답의 근거 셀(근거 셀과 다를 때만)이다. 평가 때 플래너에 보여 주지 않은 행은 흐리게 표시한다. 색만으로 뜻을 전하지 않도록 모든 표시에 글자가 붙는다.

결과의 주소는 `#workbench/<문항 id>/<플래너>`이다.

## 2026-11-20: 첫 화면을 문항 하나를 따라가는 화면으로

소유자가 화면이 복잡해 보인다고 해서 첫 화면을 바꿨다(이유와 검사는 `docs/REPORT.md` §35). 탭은 셋이다.

| 탭 | 주소 | 내용 |
|---|---|---|
| 한눈에 보기 | `#tour`, `#tour/2`, `#tour/3` (정적 데모의 기본) | 문항 하나의 질문, 모델의 제안, 도구, 검증기, 답과 정답. 옆에 그 표. 장면 셋: 통과한 답, 검증기가 셀을 고친 답, 내보내지 않은 답. 아래에 연구 결과의 결론 세 문장과 다른 탭으로 가는 링크 |
| 전체 문항 탐색 | `#workbench/<문항>/<플래너>`, `#matrix` | 위 표의 워크벤치("한 문항씩")와 문항별 결과("표로 한꺼번에"). 백엔드가 있는 실시간 모드에서는 이 탭이 기본이다 |
| 연구 결과 | `#research` | 그대로 |

작동 방식(`#about`)은 탭에서 빼고 첫 화면 아래와 페이지 맨 아래에 링크를 두었다. 맨 위의 안내 띠는 없앴다.

첫 화면의 표에 쓰는 표시는 셋이고 워크벤치의 표시와 색이 같다. 노란 바탕과 번호는 검증기가 확인한 근거 셀, 붉은 점선과 "모델"은 모델이 가리켰지만 근거가 되지 못한 셀, 회색 점선과 "같은 값"은 골라도 답이 같아지는 셀이다. 첫 화면의 요소는 워크벤치와 다른 클래스 이름(`tv-`, `tour-`)을 쓴다. 두 화면이 같은 문서 안에 있어서, 워크벤치의 표시를 지우는 코드가 첫 화면의 표시를 건드리지 않게 하려는 것이다.

## 2026-11-21: 연구 결과를 탭에서 뺌

소유자가 연구 결과 탭은 포트폴리오 형식의 내용이라 데모에 둘 까닭이 없다고 했다(`docs/REPORT.md` §35.1). 탭은 둘이다: 한눈에 보기, 전체 문항 탐색. 연구 결과 요약(`#research`)은 내용과 주소가 그대로이고 페이지 맨 아래의 링크로 간다. 작동 방식(`#about`)과 같은 자리다. 첫 화면 아래의 결론 세 문장과 링크 카드는 없앴다.
