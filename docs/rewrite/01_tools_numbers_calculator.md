테스트: `tests/test_numbers_calculator.py`. 픽스처(`medal_table`, `sales_table`, `chem_table`)는 `tests/conftest.py`에 있다. 자료형은 `src/tabletrace/schema.py`의 `CellRef`, `Table`, `CalcInput`, `Calculation`을 그대로 쓴다(이 파일은 고치지 않는다).

이 문서는 "무엇을 해야 하는지"만 적는다. 어떻게 할지(정규식을 쓸지, 한 글자씩 읽을지)는 소유자가 정한다.

> **2026-11-09 보강(첫 제출 검토 후)**: 테스트는 일부 예만 검사하므로, 테스트를 통과해도 실제 데이터에서 동작이 달라질 수 있다. 첫 제출은 테스트를 통과했지만 단위 목록이 짧아 실제 표 셀 2,329개를 다르게 읽었고, 계산기에서 `pct_change`·`count`가 빠져 있었다(명세 누락). 아래에 **동작을 원본과 같게 맞춰야 하는 이유와 규칙**을 추가했다. 끝났는지는 테스트와 함께 `python scripts/rewrite_parity.py numbers`·`calculator`로 확인한다(실제 표 6만여 셀, 헤더, 데이터셋의 모든 계산을 원본과 비교).

## `tools/numbers.py`

다른 모듈이 쓰는 공개 이름: `ParsedNumber`, `parse_number`, `header_unit`, `format_number`, `normalize_minus`, `UNIT_TOKENS`.

### `ParsedNumber`
값(`value: float`), 단위(`unit: str | None`), 원문(`raw: str`)을 담는 작은 자료형. dataclass면 충분하다.

### `normalize_minus(s: str) -> str`
유니코드 빼기 기호(`−` U+2212)와 en dash(`–` U+2013)를 ASCII `-`로 바꾼다. 표 데이터에 둘 다 섞여 있다.

### `parse_number(text: str, default_unit: str | None = None) -> ParsedNumber | None`
문자열 **전체**가 "숫자 하나(+ 선택적 단위)"일 때만 값을 돌려주고, 아니면 `None`.

받아들여야 하는 것(테스트에 있음):
- 천 단위 쉼표 `1,234`, `22,000`; 소수 `0.451`; 앞뒤 공백 `  7 `.
- 음수: ASCII `-`뿐 아니라 `−3.2`.
- 과학 표기 두 가지: `6.60 × 10−5`(곱셈 기호 `×` 또는 `x`, 10, 지수. `^`나 `**`가 끼어도 됨), `1e-6` 꼴.
- 단위가 붙은 것: `12.5%`, `−3.2 kJ/mol`, `60명`, `457 K`, `38 g/mol`. 단위는 미리 정한 목록(`UNIT_TOKENS`)에 있는 것만 인정한다. **목록은 원본의 83개를 순서까지 그대로 복사한다**(데이터이므로 복사해도 직접 작성에 해당하지 않는 부분이다). 줄이면 `1945년`, `10대`, `면적 (km2)` 같은 실제 셀·헤더 수천 개가 숫자로 읽히지 않아 검증기·기준선·합성 데이터·지표의 결과가 달라진다. 긴 토큰을 먼저 맞춰야 `g/mol`이 `g`로 잘리지 않는다. `℃`는 `°C`로 바꿔 돌려준다.
- 정수부가 없는 소수(`.5`)와 소수점 뒤가 빈 수(`12.`)는 **거부**한다. 원본이 거부하고, 받아들이면 실제 표에서 45개 셀이 새로 숫자가 된다. 지수는 절댓값 30을 넘으면 거부한다.
- 단위가 없으면 `unit`은 `None`이고, `default_unit`이 주어졌으면 그 값을 쓴다(열 헤더의 단위를 셀에 물려주는 용도. `compute`가 이 인자를 쓴다).

거부해야 하는 것(`None`):
- 범위 `1994–2010`, 날짜 `2017년 12월 20일`, 글자 `abc`, `서울`, 빈 문자열, 점이 둘인 `1.2.3`, 숫자가 둘인 `12 and 13`.
- 지수가 너무 커서 float이 무한대가 되는 `3 × 10^999`. 값을 만든 뒤 유한한지 확인하면 된다.

### `header_unit(header: str) -> str | None`
열 헤더 끝에서 단위를 뽑는다.
- 괄호 안: `매출액 (억원)` → `억원`, `Density (g/mL)` → `g/mL`, `관객수 (명)` → `명`, `득표율(%)` → `%`, `[H2O2] (M)` → `M`. 전각 괄호 `（ ）`도 같이 본다. `(단위: 억원)`처럼 "단위:" 접두가 있어도 된다.
- 쉼표 뒤: `Temperature, °C` → `°C`.
- 단위가 아닌 것은 `None`: `Radial nodes (no.)`, `Year (2015)`(숫자), `ln[H2O2]`(대괄호는 화학식). 괄호 안이 `no`, `no.`, `approx`, `est` 같은 약어이거나 숫자만이면 단위가 아니다.
- 반환하는 단위는 `parse_number`의 단위 목록과 같은 글자여야 한다(그래야 셀 단위와 열 단위를 비교할 수 있다).

### `format_number(value: float) -> str`
규칙은 이 순서로 적용한다(원본과 같아야 합성 데이터의 정답 문자열이 재현된다).
- 정수 값(소수부가 1e-9 미만)이고 절댓값이 1e15 미만이면 소수 없이 천 단위 쉼표: `1062201.0` → `1,062,201`, `0` → `0`.
- 아니면, 절댓값이 1e5 이상이거나 0이 아니면서 0.001 미만이면 과학 표기 세 자리(`f"{v:.3e}"`): `6.6e-5` → `6.600e-05`, `123456.7` → `1.235e+05`, `2.5e15` → `2.500e+15`.
- 그 외는 소수 넷째 자리까지, 천 단위 쉼표, 끝의 0과 점은 지운다: `4.51` → `4.51`, `3.92805755` → `3.9281`.

## `tools/calculator.py`

공개 이름: `CalcError`, `evaluate_expression`, `compute`. 연산은 **여섯 가지**(`diff`, `sum`, `avg`, `ratio`, `pct_change`, `count`)다. 처음 명세에 앞의 넷만 적은 것은 누락이었다. 프로그램 문법(`agent/program.py`), 휴리스틱 기준선(증가율·성장률 질문 → `pct_change`), API(`/calc`)가 여섯 가지를 모두 쓴다.

### `CalcError(ValueError)`
계산기가 거부할 때 던지는 예외. 메시지 문구가 테스트에서 검사된다: `"unit mismatch"`, `"not a single number"`, `"belongs to table"`이 들어가야 한다.

### `evaluate_expression(expr: str) -> float`
모델이 만든 식이 아니라 **우리가 만든 식**을 계산하는 함수지만, 그래도 코드 실행이 되지 않게 막는다. `eval`을 쓰지 않는다. 파이썬 `ast` 모듈로 파싱해서 허용 목록만 계산한다.
- 허용: 숫자 리터럴, 괄호, 이항 `+ - * /`, 단항 `-`/`+`.
- 거부(`CalcError`): 이름(`a + 1`), 함수 호출(`max(1,2)`, `__import__('os')`), 거듭제곱(`2 ** 100000`), 조건식(`1 if 1 else 2`), 문장 여러 개(`1; 2`), 그 밖의 모든 노드.
- 0으로 나누기(`1 / 0`)도 `CalcError`. 결과는 유한한 float.
- `(60 - 40) / 40 * 100` → `50.0`.

### `compute(table: Table, op: str, cells: list[CellRef]) -> Calculation`
표의 셀들로 계산을 실행한다. 순서대로 검사하고, 하나라도 걸리면 `CalcError`.

1. 모든 셀의 `table_id`가 `table.id`와 같아야 한다. 아니면 `"... belongs to table ..."`.
2. 각 셀의 원문을 `parse_number`로 읽는다. 단위가 없으면 그 열의 단위 `table.units.get(col)`을 `default_unit`으로 넘긴다. 숫자 하나로 읽히지 않으면(빈 칸, 글자, 범위) `"not a single number"`.
3. 모든 입력의 단위가 같아야 한다(`None`끼리도 같은 것으로 본다). 다르면 `"unit mismatch"`. 예: 억원 열과 백만원 열을 빼면 거부. **단, `count`는 값을 섞지 않으므로 이 검사를 하지 않는다.**
4. 연산:
   - `diff`: 셀 2개, `a - b`(앞 셀에서 뒤 셀을 뺀다). 식 문자열은 `"112.0 - 60.0"`처럼 값 그대로.
   - `sum`: 2개 이상, 모두 더한다.
   - `avg`: 2개 이상, 평균.
   - `ratio`: 셀 2개, `a / b`. 단위는 약분되어 `None`.
   - `pct_change`: 셀 2개(새 값, 옛 값), 식 `(a - b) / b * 100`, 단위 `%`.
   - `count`: 셀 1개 이상, 식은 셀 개수 문자열(예: `"3"`), 결과는 그 수, 단위 `None`.
   - 모르는 `op`이거나 셀 개수가 맞지 않으면 `CalcError`.
5. 계산은 식 문자열을 만들어 `evaluate_expression`에 넘겨서 한다(그래야 식과 결과가 항상 일치한다).
6. 반환 `Calculation(op, expression, inputs, result, unit, formatted)`. `inputs`는 셀마다 `CalcInput(cell, raw, value, unit)`. `unit`은 공통 단위(ratio는 `None`). `formatted`는 `format_number(result)`에 단위가 있으면 한 칸 띄우고 단위를 붙인 것: `"52"`, `"150 억원"`.

테스트의 기대값 몇 가지: 메달표 112 − 60 = 52(`expression == "112.0 - 60.0"`, `formatted == "52"`); 48 + 36 = 84; 평균 42; 매출표 1,350 − 1,200 = `"150 억원"`; 화학표 374.0 − 31.1 ≈ 342.9(단위 °C, 원문은 `−240.0`처럼 유니코드 빼기); ratio 22,000 / 1,300.

## 2026-11-09 두 번째 보강 — 첫 브랜치(`64680c9`) 리뷰에서 드러난 명세의 틀린 곳과 빠진 곳

동작 비교에서 셀 16, 표기 60, 헤더 27, 계산 62곳이 원본과 달랐다. 대부분 **명세가 틀렸거나 비어 있던 곳**이다. 아래가 원본의 정확한 동작이다. 이 단계에서는 원본과 똑같이 맞추고(차이 0개), 원본의 결함은 고치지 않고 기록만 한다(아래 "원본 결함").

1. **단위 목록에 `M`은 없다.** 처음 명세에 `M`을 넣은 것은 틀렸다. 원본 83개 그대로다. `[H2O2] (M)`의 `M`은 목록이 아니라 아래 4번의 헤더 규칙으로 나온다.
2. **지수 제한**: 지수의 절댓값이 30을 넘으면 `None`. (`1.5 × 1035`처럼 위 첨자가 깨진 셀, `12E55`, `9.1093897 × 10−31 kg`이 원본에서는 거부된다.)
3. **값 계산 방식**: 값은 `가수(쉼표 뺀 소수) × 10.0 ** 지수`로 **곱해서** 만든다. `float("4.4e-4")`처럼 문자열 e 표기로 바꾸면 마지막 비트가 달라져(`0.00044` 대 `0.00044000000000000007`), 소수 넷째 자리 반올림 결과가 바뀐다(`0.0015` 대 `0.0016`). 저장된 합성 데이터의 정답 문자열은 곱셈 방식으로 만들어졌다.
4. **`header_unit`의 괄호 규칙**: 끝의 괄호(반각·전각) 안, 선택적 `단위:` 접두 뒤의 내용이 (가) 단위 목록의 토큰이거나 (나) 영문자, `µ μ ° Ω % / · ⋅ - ^`, 숫자, 공백으로만 된 1~10글자면 단위로 인정한다. 단, 소문자로 바꿔 `no, no., approx, approx., est, est., n, a, b, c, d, e, x, y, z, i, ii, iii` 중 하나이거나 숫자로만 되어 있으면 `None`. `℃`는 `°C`로. 괄호가 없으면 쉼표 뒤가 단위 목록의 토큰일 때만 인정한다. 처음 명세의 "반환하는 단위는 단위 목록과 같은 글자여야 한다"는 틀렸다(원본은 `amu`, `V`, `kW`, `mol/L/s`처럼 목록에 없는 단위도 돌려준다).
5. **`format_number`의 정확한 순서**: (가) `abs(v - round(v)) < 1e-9`이고 `abs(v) < 1e15`이면 `round(v)`를 천 단위 쉼표 정수로, (나) 아니면 `abs(v) >= 1e5`이거나 `0 < abs(v) < 1e-3`이면 `f"{v:.3e}"`, (다) 그 외 `f"{v:,.4f}"`에서 끝의 0과 점을 지운다. (가)가 먼저라서 1e-9보다 작은 값은 `0`이 된다(아래 결함 1).

### 원본 결함 (소유자의 다시 쓰기에서 발견, `docs/dev/issues-log.md` 40·41)

- **결함 1**: `format_number`가 절댓값 1e-9 미만의 0이 아닌 값을 `0`으로 쓴다. 합성 화학 학습 데이터 4문항의 정답이 이 때문에 틀렸다(예: 중성자와 양성자의 질량 차 2.31e-27 g가 `0 g`). 소유자의 첫 구현은 이 값을 `2.310e-27 g`로 바르게 썼다.
- **결함 2**: `header_unit`의 괄호 규칙이 단위가 아닌 말(`UTC`, `MVP`, `predicted`, `measured`, `state`, `max`)도 단위로 받는다. 합성 화학 데이터 6문항의 정답에 `predicted`·`measured`가 단위로 붙었다. 소유자의 첫 구현(단위 목록만 인정)은 이것을 막았지만 대신 진짜 단위(`amu`, `V`, `kW`)를 잃었다.

두 결함을 고치면 합성 데이터와 학습 목표가 바뀌므로, 고치는 것은 이 단계가 아니라 별도 변경(데이터 재생성 포함)으로 한다. 1단계를 원본과 같게 맞춘 뒤 소유자가 수정을 제안·구현하는 순서를 권한다.
