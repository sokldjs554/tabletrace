# 자소서·포트폴리오 작성용 전달 문서 (TableTrace)

이 문서는 자기소개서와 포트폴리오를 쓰는 사람(또는 AI 도구)에게 넘기는 사실 정리다. **여기 없는 숫자는 쓰지 말고, 여기 있는 숫자도 괄호의 출처 파일로 다시 확인한 뒤 쓴다.** 저장소에서 `python scripts/check_numbers.py --strict`와 `python scripts/render_results.py --check`를 돌리면 README·보고서의 모든 숫자가 산출물과 일치하는지 검사된다(2026-11-11 기준 1034개 일치).

## 0. 반드시 지킬 규칙

1. **역할을 사실대로 적는다.** 역할은 다음과 같이 나뉜다.
   - **지원자**: 문제 정의와 핵심 설계. 모델이 답을 바로 내지 않고 프로그램(`op ; cells ; answer`)을 제안하면 도구가 실행하고 검증기가 확인해 틀리면 보류하는 구조, 한국어 표(KorWikiTQ)와 영어 화학 문서라는 두 영역, FastAPI·LangGraph·Docker·CI 스택, "실행한 것과 준비만 한 것을 나누고 숫자를 지어내지 않는다"는 보고 원칙과 공고 대조표 형식을 처음 작업 지시에서 정했다. 이후 어떤 실험을 더 하고 무엇을 건너뛸지(전체 데이터 재학습, 수작업 평가, Ampere 비교 생략)를 결정했고, GPU가 필요한 실험(EXAONE LoRA, vLLM·SGLang 서빙, 멀티 GPU)을 Kaggle·Colab에서 직접 실행해 결과를 수집했으며, 결과와 문서를 검토했다.
   - **AI 코딩 도구(Claude Code)**: 그 설계를 채우는 세부 실험 설계(표 단위 재분할, 지표, 휴리스틱 기준선, 합성 데이터 템플릿, SFT 단계, RL 보상 설계와 수정, int8 범위 실험, 검증기 v2, 쌍 비교 검정, GPU 노트북과 T4 우회 모듈)와 구현, 테스트, 문서 작성, 오류 진단. 2026-11-11의 보강(gRPC, 대화·기억, 큰 표 행 선별, 도구 호출 플래너, 표 인코더와 두 번째 의견, 화학 논문 표 세트, CPU 엔진 서버, 보강 노트북)도 무엇을 채울지는 지원자가 정했고 설계 세부와 구현은 AI 도구가 했다.
   - **소유자가 직접 다시 작성한 코드** (2026-11-10부터, `docs/rewrite/LOG.md`가 기준): AI 도구가 쓴 원본을 소유자가 명세와 테스트만 보고 처음부터 다시 쓰고, 원본과 실제 데이터에서 동작이 같은지 검사(`scripts/rewrite_parity.py`)를 통과한 뒤 소유자 계정으로 커밋·병합한 모듈. 현재: **숫자·단위 파서와 제한 계산기**(`src/tabletrace/tools/numbers.py`, `calculator.py`, PR #1), **프로그램 문법 파서·직렬화**(`src/tabletrace/agent/program.py`, PR #2), **셀 읽기·찾기·질문과 행/열의 겹침 점수**(`src/tabletrace/tools/cells.py`, PR #3), **검증기**(`src/tabletrace/verify/verifier.py`, PR #4: 셀 범위·기간·답과 셀 일치·근거 복구·재계산·단위·개체 일치 검사와 보류 결정). 그 뒤 측정에서 드러난 약점을 보고 **검증기에 근거 복구를 끄는 옵션(`repair`)을 직접 추가**했다(PR #5). 2026-11-12에는 **학습 코드 세 조각을 새로 직접 썼다**(PR #6: 강화학습 보상 `src/tabletrace/training/evidence_reward.py`, GRPO 이점·손실·KL 항 `grpo.py`, 라벨 가리기·학습률 일정·학습 루프 `lm_loop.py`. 합쳐 133줄. 원본이 없는 새 파일이라 명세와 테스트 35개만 보고 썼다. 모델 불러오기·샘플 생성·기록을 맡아 이 함수들을 불러 쓰는 `scripts/train/` 스크립트는 AI 도구가 썼다). 이 다섯 모듈로 **모델 출력을 검증하는 파이프라인의 핵심(숫자 파싱 → 프로그램 문법 → 셀 도구 → 계산기 → 검증·보류)은 소유자가 직접 구현했다**고 쓸 수 있다. 검색, 휴리스틱 기준선, 지표, LangGraph·FastAPI 서비스, 학습·평가·서빙 스크립트, 노트북, 문서는 AI 도구가 작성했다. 이 과정에서 원본 결함 2건을 찾아 기록했다(`docs/dev/issues-log.md` 40·41). 이 목록에 없는 코드는 AI 도구가 작성한 것이다.
   "혼자 다 구현했다"고 쓰면 안 되고, 반대로 "설계는 AI가 했다"고 써도 틀리다. 설계를 정하고 AI 도구를 지휘·검증한 과정, 그리고 직접 다시 쓴 모듈과 그때 찾은 결함이 내용이 된다. 직접 작성했다고 쓸 수 있는 범위는 위 목록의 모듈뿐이다.
2. **수치는 출처 파일에서만.** 모든 수치는 `experiments/` 아래 JSON에서 나오고, README와 `docs/REPORT.md`에 `<!-- num:파일:키 -->` 표식으로 묶여 있다.
3. **"주장하면 안 되는 것"(§5)을 쓰지 않는다.** 특히 "mT5로 기준선을 넘었다", "강화학습으로 점수를 올렸다", "SGLang과 vLLM 속도를 비교했다"는 틀린 말이다.
4. 실패와 수정 과정(§4)은 숨기지 말고 쓴다. 이 프로젝트의 가장 강한 재료다.
5. **공고 원문 기준으로 쓴다.** 원문은 2026-11-10에 읽었고 문구는 `docs/research/job-posting.md`에 있다. 수행 업무는 다섯 묶음(초거대 언어모델 / 심층문서이해 / 강화학습 / 테이블이해(Table MRC) / LLM 서비스·Agent)이고 채용은 "Tech Cell별"로 진행된다고 적혀 있다. **이 프로젝트는 테이블이해 묶음에 맞춘 프로젝트로 소개하고, 강화학습을 두 번째로 둔다.** 나머지 묶음의 항목은 같은 과제 위에서 실행해 본 보조 근거다. 프로젝트는 원문을 읽기 전에 지원자가 준 역량 목록 15개로 만들어졌으므로 "공고의 모든 항목을 했다"고 쓰면 안 된다. 원문에만 있는 gRPC, 챗봇, 메모리 결합, Personal Agent, 구조 전용 PLM 구현은 하지 않았다.

## 2. 프로젝트 한 문단 (사실만)

**한 줄 소개.** TableTrace는 LG AI연구원 공고의 **테이블이해(Table MRC)** 업무에 맞춘 프로젝트다. 한국어 표 질의응답에서 모델이 답과 근거 셀을 함께 내고, 고정 규칙 검증기가 그 셀로 답을 다시 확인해 맞지 않으면 보류한다. 데이터는 LG AI연구원이 공개한 KorWikiTQ다.

**먼저 말할 것은 측정 결과다.** 스택(FastAPI, LangGraph, vLLM)은 다른 지원자의 프로젝트에도 흔하므로 앞에 두지 않는다.

1. 답 텍스트가 맞은 조회 답 가운데 모델이 인용한 셀에 그 답이 없는 비율: mT5-small 52.6%(110/209), EXAONE-4.0-1.2B LoRA 300개 65.2%(245/376), 같은 모델 전체 데이터 1.3%(6/455). 답 정확도와 근거 정확도는 따로 움직이고, 데이터를 늘리면 근거 오류가 사라진다. **데이터를 늘리지 않고 입력 형식만 바꿔도 사라진다**: 같은 300개 학습에서 표의 셀마다 열 번호를 붙이면 65.2% → 3.2%(11/347)가 된다. 답 정확도는 그대로였다.
2. 검증기는 오답 유출을 21.6%에서 12.0%로 줄이고, 대가로 답하는 비율이 95.3%에서 88.7%로 준다(전체 데이터 EXAONE).
3. KorWikiTQ 공개 dev 질문의 42.9%가 train에도 있는 표를 묻는다. 표 단위로 다시 나눴다. 다만 mT5-small에서는 학습 때 본 표라고 점수가 오르지 않았다(차이 -2.3%p, 95% 구간 -6.0 ~ +1.4). 겹침은 데이터의 사실이고, 점수를 부풀린다는 주장은 하지 않는다.
4. 강화학습은 점수를 올리지 못했고, 보류가 있는 시스템에서만 생기는 보상 허점을 찾아 고쳤다.
5. 정답률은 기준선 36.2%, mT5-small 32.8%(미달), EXAONE 전체 데이터 LoRA 84.3%와 87.1%(두 번 학습).

**구조.** 모델은 답을 바로 말하지 않고 프로그램(`op: lookup|sum|avg|diff|text|abstain ; cells: r{i}c{j} ; answer: …`)을 제안한다. 도구가 그 셀을 읽고 계산을 실행하고, 검증기가 답과 근거 셀이 맞는지 확인해 틀리면 보류한다. 검색(BM25, Kiwi 형태소) → 모델 제안 → 도구 실행 → 검증 → 보류 정책 → 트레이스 기록을 FastAPI 서비스와 LangGraph 그래프로 묶었고, 비동기 작업 러너, Docker, GitHub Actions CI, GitHub Pages 데모가 있다. 모델은 두 갈래다. (가) mT5-small(300M)을 CPU에서 SFT 2단계와 GRPO 방식 RL로 튜닝했고 기준선을 넘지 못했다. (나) 같은 데이터로 EXAONE-4.0-1.2B를 LoRA 튜닝해 GPU(Kaggle T4)에서 vLLM·SGLang·텐서 병렬로 서빙한 모델은 기준선을 크게 넘었다. 영어 화학 교과서 표(OpenStax)도 같은 구조로 다뤘지만 보조 실험이다.

## 4. 포트폴리오에 쓸 만한 과정 (전부 기록이 있음)

1. **보상 허점을 찾아 고친 RL**: v1 보상은 답 없는 문항에서 최종 상태가 보류이기만 하면 만점을 줬다. 그래서 검증기가 거부하는 쓰레기 출력(같은 셀을 두 번 쓰는 계산)이 의도한 보류와 같은 점수를 받았고 그런 출력이 101건에서 160건으로 늘었다. 보상을 고친 v2는 개선이 없었고(146건), 2차 v3(프롬프트 5,130개, 검증기 v2 보상)가 "모델이 스스로 보류"를 배웠지만 전체 점수는 그대로였다. 세 결과를 다 적었다. (`docs/REPORT.md` §7, §18)
2. **학습 데이터의 지름길 발견**: 본문 예제가 전부 빈 표와 함께 있어 모델이 "표가 비면 text"를 배운 것을 찾아 재학습했고, 반대편 지름길(표 질문을 text로 보냄)까지 겪고 고쳤다. (§18.1)
3. **검증기 v2(개체 일치 검사)**: 표에 없는 대상에도 셀을 인용해 답하는 문제를 검증기 단계에서 잡았고, 정답을 오탐 보류하는 비용(4.3%)을 함께 측정했다. 잘하는 모델(EXAONE 전체)에서는 순효과가 음수에 가깝다는 것도 적었다.
4. **int8 "lm_head는 fp32"라는 문서의 오류를 스스로 발견**하고 양자화 범위별로 다시 측정해, 속도 이득은 lm_head에서 나오고 정확도 붕괴는 전체 양자화에서만 난다는 것을 보였다. (§8, §18.2)
5. **SGLang을 미지원 GPU(T4)에서 돌림**: sgl_kernel에 sm75 커널이 없어 두 번 실패 → 소스를 읽고 `MultiPlatformOp`를 PyTorch 구현으로 돌리는 우회 모듈 작성 → 세 번째는 transformers 5.x가 저장한 config.json의 RoPE 키를 4.57이 못 읽어 엉뚱한 답 → 설정 복원 → 네 번째 성공, vLLM과 답 일치. (`experiments/serving/sglang_t4_failure.md`, 이슈 37~39)
6. **숫자 정합성 도구**: 문서의 모든 숫자를 산출물 JSON에 묶는 표식과 검사 스크립트(`scripts/check_numbers.py`, `scripts/render_results.py`)로 1,541개 숫자를 자동 검증한다.
7. **학습 실행 간 변동을 측정**: 같은 설정의 LoRA를 300개 3회, 전체 2회 돌려 300개는 1점 안, 전체는 약 3점(p=0.013) 움직임을 기록하고 점수를 범위로 적었다.
8. **자기 주장을 측정으로 다시 확인하고 줄임** (2026-11-10): "공개 분할이 표 1,755개를 공유한다"는 문장이 실은 페이지 수였음을 찾아 고쳤다(같은 표는 1,578개). "표 겹침이 점수를 부풀린다"는 가정은 직접 재 보니 mT5에서 검출되지 않았고, 그 결과를 그대로 적었다. (`docs/REPORT.md` §19.3, 이슈 42)
9. **가까운 논문 12편을 원문으로 읽고 주장 범위를 정함**: 답과 근거의 불일치, 셀 인용 강화학습, 근거 셀 보상은 이미 연구가 있다는 것을 확인하고 "새롭다"는 표현을 빼고 "한국어 표에서의 측정"으로 좁혔다. KorWikiTQ 원논문이 분할 방식을 밝히지 않는다는 것도 원문에서 확인했다. (§8, `docs/research/papers.md`)
12. **측정에서 찾은 약점을 본인 코드에 옵션으로 넣고 직접 확인** (2026-11-11): 검증기의 근거 복구가 약한 모델의 점수와 오답을 함께 올린다는 측정을 보고, 직접 쓴 검증기에 복구를 끄는 옵션을 추가했다(PR #5, 3줄). 기본 동작이 그대로인지 29,100건으로 확인하고, 옵션을 켠 재검증 6,990문항이 앞서 계산한 값과 모두 같음을 확인했다. (`docs/REPORT.md` §19.8)
11. **측정에서 원인을 짚고 입력 형식으로 고침** (2026-11-10): 근거 오류가 거의 전부 "행은 맞고 열이 틀림"이라는 측정에서, 모델이 열 번호를 세어야 하는 입력 형식이 원인이라고 보고 셀마다 열 번호를 붙이는 형식을 추가했다. 토큰 비용을 먼저 재서 공정한 입력 예산(800)을 정한 뒤 Kaggle에서 돌렸고, 근거 오류가 65% → 3%로 줄었다. 정답률이 오르지 않은 것과 검증기를 통과하는 오답이 늘어난 것도 함께 적었다. (§19.7)
10. **답은 맞는데 근거가 틀린 비율을 따로 잼**: verified EM만 보면 가려지는 것을 드러냈다. 약한 모델은 맞힌 답의 절반 이상에서 답이 없는 셀을 인용했고, 검증기의 근거 복구가 점수를 지탱하고 있었다. 전체 데이터 학습 뒤에는 1.3%가 됐다. (§19.1)

## 5. 주장하면 안 되는 것

- "mT5로 기준선보다 좋은 모델을 만들었다" (32.8% 대 36.2%, 못 넘었다).
- "강화학습으로 ko test 점수를 올렸다" (v3도 그대로. 배운 것은 보류 행동).
- "EXAONE이 실제 표의 계산을 잘한다" (계산·보류 평가 문항은 학습과 같은 템플릿의 합성 데이터. 실제 표 문항은 전부 조회).
- "SGLang과 vLLM의 성능을 비교했다" (T4의 SGLang은 우회 모듈 탓에 느림. Ampere 이상에서의 비교는 비용 때문에 하지 않음).
- "멀티 GPU로 속도를 올렸다" (파이프라인 병렬은 이득 없음. TP=2만 처리량 약 1.6배).
- "한국어 표 PLM을 사전학습했다" (표 사전학습은 수천 개 표로 수백 step 돌린 작은 실험이다. "사전학습 모델에 행·열 임베딩과 셀 선택 헤드를 붙인 표 인코더를 구현하고 작은 규모로 학습했다"가 맞는 말이다).
- "화학 논문으로 학습했다" (학습은 교과서 표다. 논문 표는 평가용 62문항뿐이다), "DDP로 GPU 학습을 했다" (구현과 CPU 두 프로세스 시험만 했다), "혼자 코드를 짰다" (AI 도구가 작성).
- "LLM 챗봇을 만들었다" (대화는 규칙으로 후속 질문을 완성하는 방식이다. 언어모델이 대화를 관리하지 않는다. "여러 턴 대화와 기억을 규칙 기반으로 붙였다"가 맞는 말이다).
- "모델이 도구를 스스로 고르는 에이전트로 성능을 냈다" (구현하고 모의 서버로 시험했고, 실제 모델은 CPU에서 튜닝하지 않은 1.2B로 30문항만 돌렸다. 그 결과는 낮다. 튜닝한 모델이나 큰 모델의 결과는 없다).
- "큰 EXAONE(7.8B, 32B)을 썼다", "EXAONE에 강화학습을 했다", "학습 데이터를 3만 개로 늘렸다", "4비트 양자화 서빙을 했다" (전부 노트북까지 준비한 것이다. GPU 결과가 저장소에 들어오기 전에는 쓰지 않는다).
- "학습 스크립트를 전부 직접 짰다", "EXAONE 강화학습을 돌렸다" (직접 쓴 학습 코드는 보상 함수, GRPO 이점·손실, 학습 루프 세 파일이다(PR #6). "강화학습 보상과 손실, 학습 루프를 명세와 테스트를 받아 직접 구현했다"까지 쓸 수 있다. 그 함수를 불러 쓰는 스크립트와 mT5 학습 코드는 AI 도구가 썼고, EXAONE 강화학습은 GPU에서 아직 돌리지 않았다).
- "공개 dev 점수가 논문과 비슷하다/낮다" (학습에 없던 표만 골랐고, 근거 셀까지 채점하고, 모델이 다르다. 나란히 놓을 수 없다).
- "처음", "최초", "새로운 방법" (가까운 논문 12편을 원문으로 읽었다. 답과 근거의 불일치는 TrustTable(ACL 2026)과 ViTaB-A가, 작은 모델의 셀 인용 강화학습은 RSAT가, 근거 셀 보상과 그 위험은 Reasoning-Table이 이미 다룬다. §8 참고).
- "표 1,755개가 겹친다" (1,755는 페이지 수다. 셀까지 같은 표는 1,578개다).
- "검증기가 틀린 근거를 걸러 낸다" (답 텍스트가 표의 한 셀과 같으면 검증기는 근거를 그 셀로 고쳐서 답한다. 걸러 내는 것은 답과 셀이 안 맞는 경우다).
- "열 번호 형식으로 정답률을 올렸다" (줄어든 것은 근거 셀 오류다. 정답률은 그대로였고 검증기를 통과하는 오답은 늘었다. 300개 설정에서 한 번 실행한 결과이고 전체 데이터에서는 재지 않았다. `docs/REPORT.md` §19.7).
- "공고의 모든 항목을 같은 깊이로 구현했다" (원문에만 있던 gRPC, 챗봇, 메모리 결합, Personal Agent, 구조 이해 PLM은 2026-11-11에 좁은 범위로 더했다. 프로젝트의 중심은 여전히 테이블이해이고, 나머지는 "있다" 수준이다. §9 참고).

## 7. ko-search-clinic과 역할 나누기

지원자의 다른 공개 저장소 <https://github.com/sokldjs554/ko-search-clinic>도 한국어를 다루고 Kiwi 형태소 분석과 BM25를 쓴다. 두 저장소를 같은 이야기로 쓰면 "한국어 검색 프로젝트 두 개"로 읽힌다. 다음과 같이 나눠 쓴다.

| | ko-search-clinic | TableTrace |
|---|---|---|
| 질문 | 한국어 검색이 왜 실패하고, 어떤 수정안이 실제로 검색을 고치는가 | 표를 읽는 모델이 낸 답의 근거 셀이 맞는가, 틀리면 어떻게 막는가 |
| 모델 학습 | 없음 (규칙, 임베딩, GPT·Claude 후보를 회귀 게이트로 검증) | 있음 (mT5 SFT·강화학습, EXAONE LoRA) |
| 평가 대상 | 검색 순위(nDCG, Recall), 인용 원문 일치 | 답과 근거 셀, 보류, 검증된 정답률 |
| 공고에서 맞는 묶음 | LLM 서비스·Agent (검색 결합, 서비스 품질 개선) | 테이블이해(Table MRC), 강화학습 |
| 검색(BM25·Kiwi)의 지위 | 연구 대상 | 표를 찾아 오는 앞 단계. 연구 대상이 아님 |

두 저장소의 공통점은 "모델 출력을 그대로 믿지 않고 규칙으로 검증한다"는 태도다. 이것은 한 문장으로 묶어 써도 된다. TableTrace 쪽에서 검색이나 FastAPI를 길게 쓰면 ko-search-clinic과 겹치므로, 근거 셀 측정·검증기·학습 실험을 중심으로 쓴다.

## 8. 선행 연구 대비 주장 범위

쓸 수 있는 문장: "한국어 표 질의응답에서, 답과 근거 셀을 함께 내는 작은 모델의 근거 오류를 정답 셀 기준으로 재고, 고정 규칙 검증기와 보류로 오답 유출을 줄이는 폭을 수치로 보였다." 12편에 한국어 표의 근거 셀 평가는 없었다. 그렇다고 "처음"이라고 쓰지는 않는다. 12편만 봤기 때문이다.

**소유자가 직접 읽은 논문.** 위 12편과 국내 연구 8편은 AI가 읽고 정리했다. 소유자가 전에 읽었다고 알려 준 것은 한양대 논문 두 편이다(2026-11-11, `docs/research/papers.md`의 "소유자가 읽은 한양대 논문 두 편"). 자기소개서나 면접에서 "읽은 논문"으로 말할 수 있는 것은 소유자가 직접 읽은 것뿐이다.

### 9.2 구현하고 CPU에서 시험만 한 것 ("구현했다"까지만 쓴다)

- **모델이 도구를 고르는 에이전트(Tool Calling)**: 모델이 표 본문 없이 도구로 표를 읽고 제출한다. 대본대로 답하는 모의 서버로 테스트 6개. 실제 모델로는 CPU에서 튜닝하지 않은 EXAONE-4.0-1.2B로 수작업 30문항만 돌렸다: verified EM 16.7%(5/30, 전부 답 없는 질문의 보류), 같은 모델의 한 줄 답 방식 20.0%, 튜닝한 같은 크기 모델 66.7%. "경로가 실제 모델로 끝까지 돈다"까지만 쓴다. "도구 호출로 성능을 올렸다"는 틀린 말이다(`experiments/eval/tool_calling_cpu.json`).
- **멀티 GPU 학습(DDP)**: `torchrun` 아래에서 프로세스마다 데이터 조각을 맡는다. CPU 두 프로세스 시험 통과. GPU 실행 없음.
- **EXAONE 강화학습 스크립트**: 표본 생성·기록·저장을 맡고, 보상과 손실은 본인이 쓴 모듈(PR #6)을 불러 쓴다. 작은 무작위 모델로 한 바퀴 도는 것만 확인.
- **본인이 직접 쓴 학습 코드**(2026-11-12, PR #6): 보상 함수, GRPO 이점·손실·KL 항, 라벨 가리기·학습률 일정·학습 루프. 전용 테스트 35개 통과. 리뷰에서 보상 함수를 저장된 모델 출력 66,450회 호출에 적용해 AI 도구의 임시 구현과 차이가 없음을 확인했다(`docs/rewrite/LOG.md`). "직접 구현했다"고 쓸 수 있다. 이 코드로 학습한 결과는 아직 없다(노트북 D절).
- **큰 모델 참고선용 few-shot 평가, 엔진의 확신도 저장**: 평가 러너의 옵션으로 있고 모의 서버 테스트가 있다. (mT5의 확신도 저장은 실제로 돌렸다. 9.1 참고)

### 9.4 면접에서 물으면

- "챗봇을 만들었나" → 한 건짜리 검증 파이프라인 위에 세션 기억과 사용자 기억을 얹고, 후속 질문을 규칙 세 가지로 완성하게 했다. 언어모델이 대화를 관리하지 않게 한 이유는 무엇을 채웠는지 설명할 수 있어야 해서다. 평가의 후속 질문은 틀로 만든 것이라 자연 대화 성능은 모른다.
- "Tool Calling은" → 구현하고 모의 서버로 검증했고, GPU가 없어 CPU에서 튜닝하지 않은 EXAONE-4.0-1.2B로 30문항만 돌려 봤다고 말한다. 경로는 끝까지 돌았지만 모델이 셀을 한 번 찾아본 뒤 대부분 보류해서 정답률은 16.7%였다. 큰 모델로 재는 것(노트북 A2절)과 도구 호출 형식으로 튜닝하는 것이 다음 단계다.
- "큰 표는" → 처음에는 작은 모델의 입력 길이 때문에 뺐고, 나중에 행 선별을 넣어 공개 dev의 처음 보는 표로 쟀다. 절대 점수가 낮은 것(mT5 37.8%)도 같이 말한다.
- "화학 논문은" → 평가용 표 20개를 공개 라이선스 논문에서 뽑았다. 학습은 교과서 표다. 특허는 없다.
- "학습 코드를 직접 짰나" → 범위를 나눠 말한다. 직접 쓴 것은 보상 함수, GRPO의 이점과 손실, 미세조정 학습 루프다(133줄). 명세와 테스트는 AI 도구가 썼고 그것을 보고 구현했다. 설명할 수 있어야 하는 것: 보상을 다섯 단계로 나눈 이유(답 없는 질문에서 검증기가 거부한 출력에 점수를 주지 않는다), 그룹 안에서 이점을 정규화하는 이유, 로그 확률을 한 칸 어긋나게 읽는 이유, 손실을 누적 횟수로 나누는 이유, 검증기 예외를 보류로 처리한 이유.
- "어떤 논문을 읽었나" → 직접 읽은 것과 조사에 AI를 쓴 것을 나눠 말한다. 직접 읽은 것으로 확인된 것은 한양대 두 편이다(8절). RFL은 "틀린 문항을 골라 다시 가르친다"는 점에서 이 프로젝트의 강화학습과 이어지고, 루브릭 논문은 "LLM 판정은 설정에 민감하다"는 점에서 규칙 검증기를 고른 이유와 이어진다. 두 논문의 수치를 말할 때는 원문의 표를 다시 보고 말한다.
