# 자소서·포트폴리오 작성용 전달 문서 (TableTrace)

이 문서는 자기소개서와 포트폴리오를 쓰는 사람(또는 AI 도구)에게 넘기는 사실 정리다. **여기 없는 숫자는 쓰지 말고, 여기 있는 숫자도 괄호의 출처 파일로 다시 확인한 뒤 쓴다.** 저장소에서 `python scripts/check_numbers.py --strict`와 `python scripts/render_results.py --check`를 돌리면 README·보고서의 모든 숫자가 산출물과 일치하는지 검사된다(2026-11-11 기준 1034개 일치).

## 0. 반드시 지킬 규칙

1. **역할을 사실대로 적는다.** 역할은 다음과 같이 나뉜다.
   - **지원자**: 문제 정의와 핵심 설계. 모델이 답을 바로 내지 않고 프로그램(`op ; cells ; answer`)을 제안하면 도구가 실행하고 검증기가 확인해 틀리면 보류하는 구조, 한국어 표(KorWikiTQ)와 영어 화학 문서라는 두 영역, FastAPI·LangGraph·Docker·CI 스택, "실행한 것과 준비만 한 것을 나누고 숫자를 지어내지 않는다"는 보고 원칙과 공고 대조표 형식을 처음 작업 지시에서 정했다. 이후 어떤 실험을 더 하고 무엇을 건너뛸지(전체 데이터 재학습, 수작업 평가, Ampere 비교 생략)를 결정했고, GPU가 필요한 실험(EXAONE LoRA, vLLM·SGLang 서빙, 멀티 GPU)을 Kaggle·Colab에서 직접 실행해 결과를 수집했으며, 결과와 문서를 검토했다.
   - **AI 코딩 도구(Claude Code)**: 그 설계를 채우는 세부 실험 설계(표 단위 재분할, 지표, 휴리스틱 기준선, 합성 데이터 템플릿, SFT 단계, RL 보상 설계와 수정, int8 범위 실험, 검증기 v2, 쌍 비교 검정, GPU 노트북과 T4 우회 모듈)와 구현, 테스트, 문서 작성, 오류 진단. 2026-11-11의 보강(gRPC, 대화·기억, 큰 표 행 선별, 도구 호출 플래너, 표 인코더와 두 번째 의견, 화학 논문 표 세트, CPU 엔진 서버, 보강 노트북)도 무엇을 채울지는 지원자가 정했고 설계 세부와 구현은 AI 도구가 했다.
   - **소유자가 직접 다시 작성한 코드** (2026-11-10부터, `docs/rewrite/LOG.md`가 기준): AI 도구가 쓴 원본을 소유자가 명세와 테스트만 보고 처음부터 다시 쓰고, 원본과 실제 데이터에서 동작이 같은지 검사(`scripts/rewrite_parity.py`)를 통과한 뒤 소유자 계정으로 커밋·병합한 모듈. 현재: **숫자·단위 파서와 제한 계산기**(`src/tabletrace/tools/numbers.py`, `calculator.py`, PR #1), **프로그램 문법 파서·직렬화**(`src/tabletrace/agent/program.py`, PR #2), **셀 읽기·찾기·질문과 행/열의 겹침 점수**(`src/tabletrace/tools/cells.py`, PR #3), **검증기**(`src/tabletrace/verify/verifier.py`, PR #4: 셀 범위·기간·답과 셀 일치·근거 복구·재계산·단위·개체 일치 검사와 보류 결정). 그 뒤 측정에서 드러난 약점을 보고 **검증기에 근거 복구를 끄는 옵션(`repair`)을 직접 추가**했다(PR #5). 2026-11-12에는 **학습 코드 세 조각을 새로 직접 썼다**(PR #6: 강화학습 보상 `src/tabletrace/training/evidence_reward.py`, GRPO 이점·손실·KL 항 `grpo.py`, 라벨 가리기·학습률 일정·학습 루프 `lm_loop.py`. 합쳐 133줄. 원본이 없는 새 파일이라 명세와 테스트 35개만 보고 썼다. 보상과 손실은 EXAONE 강화학습 다섯 번에 실제로 쓰였다. **학습 루프로는 전체 데이터 미세조정을 한 번 했다**(2026-11-16, test 86.0%, 9.1g). 그 밖의 EXAONE 미세조정(대표 수치의 모델 포함)은 모두 AI 도구가 쓴 스크립트의 루프로 돌았다. 모델 불러오기·샘플 생성·기록을 맡아 이 함수들을 불러 쓰는 `scripts/train/` 스크립트는 AI 도구가 썼다). 이 다섯 모듈로 **모델 출력을 검증하는 파이프라인의 핵심(숫자 파싱 → 프로그램 문법 → 셀 도구 → 계산기 → 검증·보류)은 소유자가 직접 구현했다**고 쓸 수 있다. 검색, 휴리스틱 기준선, 지표, LangGraph·FastAPI 서비스, 학습·평가·서빙 스크립트, 노트북, 문서는 AI 도구가 작성했다. 이 과정에서 원본 결함 2건을 찾아 기록했다(`docs/dev/issues-log.md` 40·41). 이 목록에 없는 코드는 AI 도구가 작성한 것이다. 코드가 아닌 것으로는 2026-11-16에 **한국어 평가 문항 30개를 직접 썼고**(`data/ko/owner_eval.jsonl`) **AI 도구가 쓴 수작업 30문항을 검수했다**(`data/ko/custom_eval_review.jsonl`, PR #7, 9.1f). 그 밖의 평가 문항(한국어 수작업 30, 화학 94)과 합성 데이터의 틀은 AI 도구가 썼다.
   "혼자 다 구현했다"고 쓰면 안 되고, 반대로 "설계는 AI가 했다"고 써도 틀리다. 설계를 정하고 AI 도구를 지휘·검증한 과정, 그리고 직접 다시 쓴 모듈과 그때 찾은 결함이 내용이 된다. 직접 작성했다고 쓸 수 있는 범위는 위 목록의 모듈뿐이다.
2. **수치는 출처 파일에서만.** 모든 수치는 `experiments/` 아래 JSON에서 나오고, README와 `docs/REPORT.md`에 `<!-- num:파일:키 -->` 표식으로 묶여 있다.
3. **"주장하면 안 되는 것"(§5)을 쓰지 않는다.** 특히 "mT5로 기준선을 넘었다", "mT5 강화학습으로 점수를 올렸다", "강화학습이 미세조정보다 낫다", "SGLang과 vLLM 속도를 비교했다"는 틀린 말이다. EXAONE 강화학습은 두 번째 실험에서 근거 셀 정확도가 올랐고(한 번 더 돌려 같은 결과), 대조군으로 그 조건(학습 배치를 실제 문항 비율로 뽑기)을 확인했다. 쓸 수 있는 문장은 9.1c에 있다. "프롬프트 잘림이 첫 실험의 실패 원인이었다"는 틀린 말이다(대조군은 프롬프트가 온전했는데도 무너졌다). "미세조정한 모델에 강화학습을 더해 더 좋아졌다"도 틀린 말이다(전체 데이터 모델에서 시작하면 정답률에 차이가 없었다, 9.1e).
4. 실패와 수정 과정(§4)은 숨기지 말고 쓴다. 이 프로젝트의 가장 강한 재료다.
5. **공고 원문 기준으로 쓴다.** 원문은 2026-11-10에 읽었고 2026-11-16에 다시 받아 같은 문구임을 확인했다. 문구는 `docs/research/job-posting.md`에 있다. 지원 전 마지막 대조와 남은 약점은 §10에 있다. 수행 업무는 다섯 묶음(초거대 언어모델 / 심층문서이해 / 강화학습 / 테이블이해(Table MRC) / LLM 서비스·Agent)이고 채용은 "Tech Cell별"로 진행된다고 적혀 있다. **이 프로젝트는 테이블이해 묶음에 맞춘 프로젝트로 소개하고, 강화학습을 두 번째로 둔다.** 나머지 묶음의 항목은 같은 과제 위에서 실행해 본 보조 근거다. 프로젝트는 원문을 읽기 전에 지원자가 준 역량 목록 15개로 만들어졌으므로 "공고의 모든 항목을 했다"고 쓰면 안 된다. 원문에만 있는 gRPC, 챗봇, 메모리 결합, Personal Agent, 구조 전용 PLM 구현은 하지 않았다.
6. **논문은 직접 읽은 것만 이름을 댄다**(2026-11-16 결정). 직접 읽은 것은 한양대 두 편이다(§8). AI 도구가 조사한 논문들은 서류, 포트폴리오, 면접에서 이름을 대지 않는다. "비슷한 연구가 있느냐"고 물으면 "있다는 것을 조사로 확인했고, 그래서 새로운 방법이라고 주장하지 않는다"까지만 말한다. 데이터 출처(KorWikiTQ, arXiv 화학 논문의 표)는 출처로 밝힌다. 그것은 논문을 읽었다는 말이 아니다.

## 2. 프로젝트 한 문단 (사실만)

**한 줄 소개.** TableTrace는 LG AI연구원 공고의 **테이블이해(Table MRC)** 업무에 맞춘 프로젝트다. 한국어 표 질의응답에서 모델이 답과 근거 셀을 함께 내고, 고정 규칙 검증기가 그 셀로 답을 다시 확인해 맞지 않으면 보류한다. 데이터는 LG AI연구원이 공개한 KorWikiTQ다.

**먼저 말할 것은 측정 결과다.** 스택(FastAPI, LangGraph, vLLM)은 다른 지원자의 프로젝트에도 흔하므로 앞에 두지 않는다.

1. 답 텍스트가 맞은 조회 답 가운데 모델이 인용한 셀에 그 답이 없는 비율: mT5-small 52.6%(110/209), EXAONE-4.0-1.2B LoRA 300개 65.2%(245/376), 같은 모델 전체 데이터 1.3%(6/455). 답 정확도와 근거 정확도는 따로 움직이고, 데이터를 늘리면 근거 오류가 사라진다. **데이터를 늘리지 않고 입력 형식만 바꿔도 사라진다**: 같은 300개 학습에서 표의 셀마다 열 번호를 붙이면 65.2% → 3.2%(11/347)가 된다. 답 정확도는 그대로였다.
2. 검증기는 오답 유출을 21.6%에서 12.0%로 줄이고, 대가로 답하는 비율이 95.3%에서 88.7%로 준다(전체 데이터 EXAONE).
3. KorWikiTQ 공개 dev 질문의 42.9%가 train에도 있는 표를 묻는다. 표 단위로 다시 나눴다. 다만 mT5-small에서는 학습 때 본 표라고 점수가 오르지 않았다(차이 -2.3%p, 95% 구간 -6.0 ~ +1.4). 겹침은 데이터의 사실이고, 점수를 부풀린다는 주장은 하지 않는다.
4. 강화학습은 mT5-small에서 점수를 올리지 못했고, 보류가 있는 시스템에서만 생기는 보상 허점을 찾아 고쳤다. EXAONE 1.2B에서는 첫 실험이 듣지 않았고, 학습 스크립트의 두 가지(프롬프트 잘림, 배치 구성)를 고친 두 번째 실험에서 300문항 튜닝 모델의 인용 셀 정확도가 26.2% → 43.8%, verified EM이 55.2% → 59.4%가 됐다(같은 699문항 대응 검정 p <0.001). 시작 모델을 달리해 한 번 더 돌려도 같았다(인용 셀 정확도 25.7% → 46.7%). 같은 시작 모델에서 배치 구성만 첫 실험처럼 되돌린 대조군에서는 인용 셀 정확도가 오르지 않았다(25.7% → 26.5%, 두 실험의 변화의 차이 p <0.001). 근거 셀의 개선은 학습 배치를 실제 문항 비율로 뽑을 때만 나타났다. 전체 데이터 미세조정(84.3%)에는 못 미친다. 전체 데이터로 미세조정한 모델에서 시작하면 정답률에 차이가 없었고(86.0%와 86.1%, 같은 699문항에서 한쪽만 맞힌 것이 8개와 7개), 그 실행에서 확신도의 변별력은 떨어졌다(9.1e).
5. 정답률은 기준선 36.2%, mT5-small 32.8%(미달), EXAONE 전체 데이터 LoRA는 여섯 번의 학습에서 84.3%, 87.1%, 87.0%(이상 예전 설정), 86.4%, 86.0%, 85.5%(이상 고친 설정)다. 직접 쓴 학습 루프로 한 일곱 번째 학습은 86.0%다(9.1g). 대표 수치로는 가장 낮은 1회째(84.3%)를 쓴다. 학습 스크립트에 긴 예제의 정답이 잘리는 결함이 있었는데, 고쳐서 다시 학습해도 차이가 검출되지 않았다(같은 세션에서 같은 문항 23 대 27).

**구조.** 모델은 답을 바로 말하지 않고 프로그램(`op: lookup|sum|avg|diff|text|abstain ; cells: r{i}c{j} ; answer: …`)을 제안한다. 도구가 그 셀을 읽고 계산을 실행하고, 검증기가 답과 근거 셀이 맞는지 확인해 틀리면 보류한다. 검색(BM25, Kiwi 형태소) → 모델 제안 → 도구 실행 → 검증 → 보류 정책 → 트레이스 기록을 FastAPI 서비스와 LangGraph 그래프로 묶었고, 비동기 작업 러너, Docker, GitHub Actions CI, GitHub Pages 데모가 있다. 모델은 두 갈래다. (가) mT5-small(300M)을 CPU에서 SFT 2단계와 GRPO 방식 RL로 튜닝했고 기준선을 넘지 못했다. (나) 같은 데이터로 EXAONE-4.0-1.2B를 LoRA 튜닝해 GPU(Kaggle T4)에서 vLLM·SGLang·텐서 병렬로 서빙한 모델은 기준선을 크게 넘었다. 영어 화학 교과서 표(OpenStax)도 같은 구조로 다뤘지만 보조 실험이다.

## 4. 포트폴리오에 쓸 만한 과정 (전부 기록이 있음)

1. **보상 허점을 찾아 고친 RL**: v1 보상은 답 없는 문항에서 최종 상태가 보류이기만 하면 만점을 줬다. 그래서 검증기가 거부하는 쓰레기 출력(같은 셀을 두 번 쓰는 계산)이 의도한 보류와 같은 점수를 받았고 그런 출력이 101건에서 160건으로 늘었다. 보상을 고친 v2는 개선이 없었고(146건), 2차 v3(프롬프트 5,130개, 검증기 v2 보상)가 "모델이 스스로 보류"를 배웠지만 전체 점수는 그대로였다. 세 결과를 다 적었다. (`docs/REPORT.md` §7, §18)
2. **학습 데이터의 지름길 발견**: 본문 예제가 전부 빈 표와 함께 있어 모델이 "표가 비면 text"를 배운 것을 찾아 재학습했고, 반대편 지름길(표 질문을 text로 보냄)까지 겪고 고쳤다. (§18.1)
3. **검증기 v2(개체 일치 검사)**: 표에 없는 대상에도 셀을 인용해 답하는 문제를 검증기 단계에서 잡았고, 정답을 오탐 보류하는 비용(4.3%)을 함께 측정했다. 잘하는 모델(EXAONE 전체)에서는 순효과가 음수에 가깝다는 것도 적었다.
4. **int8 "lm_head는 fp32"라는 문서의 오류를 스스로 발견**하고 양자화 범위별로 다시 측정해, 속도 이득은 lm_head에서 나오고 정확도 붕괴는 전체 양자화에서만 난다는 것을 보였다. (§8, §18.2)
5. **SGLang을 미지원 GPU(T4)에서 돌림**: sgl_kernel에 sm75 커널이 없어 두 번 실패 → 소스를 읽고 `MultiPlatformOp`를 PyTorch 구현으로 돌리는 우회 모듈 작성 → 세 번째는 transformers 5.x가 저장한 config.json의 RoPE 키를 4.57이 못 읽어 엉뚱한 답 → 설정 복원 → 네 번째 성공, vLLM과 답 일치. (`experiments/serving/sglang_t4_failure.md`, 이슈 37~39)
6. **숫자 정합성 도구**: 문서의 모든 숫자를 산출물 JSON에 묶는 표식과 검사 스크립트(`scripts/check_numbers.py`, `scripts/render_results.py`)로 1,541개 숫자를 자동 검증한다.
7. **학습 실행 간 변동을 측정**: 같은 설정의 LoRA를 300개 3회, 전체 2회 돌려 300개는 1점 안, 전체는 약 3점(p=0.013) 움직임을 기록하고 점수를 범위로 적었다.
8. **자기 주장을 측정으로 다시 확인하고 줄임** (2026-11-10): "공개 분할이 표 1,755개를 공유한다"는 문장이 실은 페이지 수였음을 찾아 고쳤다(같은 표는 1,578개). "표 겹침이 점수를 부풀린다"는 가정은 직접 재 보니 mT5에서 검출되지 않았고, 그 결과를 그대로 적었다. (`docs/REPORT.md` §19.3, 이슈 42)
12. **측정에서 찾은 약점을 본인 코드에 옵션으로 넣고 직접 확인** (2026-11-11): 검증기의 근거 복구가 약한 모델의 점수와 오답을 함께 올린다는 측정을 보고, 직접 쓴 검증기에 복구를 끄는 옵션을 추가했다(PR #5, 3줄). 기본 동작이 그대로인지 29,100건으로 확인하고, 옵션을 켠 재검증 6,990문항이 앞서 계산한 값과 모두 같음을 확인했다. (`docs/REPORT.md` §19.8)
11. **측정에서 원인을 짚고 입력 형식으로 고침** (2026-11-10): 근거 오류가 거의 전부 "행은 맞고 열이 틀림"이라는 측정에서, 모델이 열 번호를 세어야 하는 입력 형식이 원인이라고 보고 셀마다 열 번호를 붙이는 형식을 추가했다. 토큰 비용을 먼저 재서 공정한 입력 예산(800)을 정한 뒤 Kaggle에서 돌렸고, 근거 오류가 65% → 3%로 줄었다. 정답률이 오르지 않은 것과 검증기를 통과하는 오답이 늘어난 것도 함께 적었다. (§19.7)
10. **답은 맞는데 근거가 틀린 비율을 따로 잼**: verified EM만 보면 가려지는 것을 드러냈다. 약한 모델은 맞힌 답의 절반 이상에서 답이 없는 셀을 인용했고, 검증기의 근거 복구가 점수를 지탱하고 있었다. 전체 데이터 학습 뒤에는 1.3%가 됐다. (§19.1)

## 5. 주장하면 안 되는 것

- "mT5로 기준선보다 좋은 모델을 만들었다" (32.8% 대 36.2%, 못 넘었다).
- "mT5 강화학습으로 ko test 점수를 올렸다" (v3도 그대로. 배운 것은 보류 행동).
- "EXAONE이 실제 표의 계산을 잘한다" (계산·보류 평가 문항은 학습과 같은 템플릿의 합성 데이터. 실제 표 문항은 전부 조회).
- "SGLang과 vLLM의 성능을 비교했다" (T4의 SGLang은 우회 모듈 탓에 느림. Ampere 이상에서의 비교는 비용 때문에 하지 않음).
- "멀티 GPU로 속도를 올렸다" (파이프라인 병렬은 이득 없음. TP=2만 처리량 약 1.6배).
- "한국어 표 PLM을 사전학습했다" (표 사전학습은 수천 개 표로 수백 step 돌린 작은 실험이다. "사전학습 모델에 행·열 임베딩과 셀 선택 헤드를 붙인 표 인코더를 구현하고 작은 규모로 학습했다"가 맞는 말이다).
- "화학 논문으로 학습했다" (학습은 교과서 표다. 논문 표는 평가용 62문항뿐이다), "DDP로 성능을 올렸다" (GPU 두 장 학습의 속도 1.83배만 쟀다. 9.1b), "혼자 코드를 짰다" (AI 도구가 작성).
- "LLM 챗봇을 만들었다" (대화는 규칙으로 후속 질문을 완성하는 방식이다. 언어모델이 대화를 관리하지 않는다. "여러 턴 대화와 기억을 규칙 기반으로 붙였다"가 맞는 말이다).
- "모델이 도구를 스스로 고르는 에이전트로 성능을 냈다" (튜닝하지 않은 1.2B와 32B로 GPU에서 쟀고, 둘 다 같은 모델이 프로그램 한 줄을 쓰는 방식보다 낮다. 도구 호출 형식으로 튜닝한 모델은 없다. 9.1b, 9.1c).
- "큰 EXAONE(7.8B, 32B)을 튜닝했다" (튜닝 없이 예시 6개만 주고 같은 검증기로 쟀다), "학습 데이터를 3만 개로 늘렸다" (10,587문항까지 늘렸다), "튜닝한 모델을 4비트로 서빙했다" (4비트는 AWQ로 배포된 7.8B와 32B를 올린 것이다. 튜닝한 모델의 4비트 서빙은 하지 못했다).
- "학습 스크립트를 전부 직접 짰다" (직접 쓴 학습 코드는 보상 함수, GRPO 이점·손실, 학습 루프 세 파일이다(PR #6). 그 함수를 불러 쓰는 스크립트와 mT5 학습 코드는 AI 도구가 썼다).
- "강화학습이 미세조정보다 낫다", "강화학습으로 계산 문항을 풀게 됐다", "효과의 원인은 프롬프트 수정이다", "프롬프트 잘림 때문에 첫 실험이 실패했다", "두 번째 실험이 대조군보다 verified EM을 유의하게 더 올렸다", "미세조정한 모델에 강화학습을 더해 더 좋아졌다", "강화학습이 모델의 확신도를 망친다" (EXAONE 1.2B에 다섯 번 적용했다: 첫 실험, 두 번째 실험과 그 반복, 대조군, 전체 데이터 모델에서 시작한 실험. 첫 실험은 근거 셀 오류가 줄지 않았다(`docs/REPORT.md` §21.1). 두 번째 실험은 300문항 모델에서 시작해 59.4%이고 전체 데이터 미세조정은 84.3%다. 계산 문항은 틀린 답이 보류로 바뀌었을 뿐이다. 대조군은 프롬프트가 온전했는데도 첫 실험처럼 무너졌으므로, 결과를 가른 것은 배치 구성이다. verified EM은 대조군과 유의하게 다르지 않다(변화량 비교 p 0.170, 같은 시작 모델에서의 직접 비교 p 0.119). 유의하게 다른 것은 근거 셀과 틀린 답의 수다(§22.7, §22.8). 전체 데이터 모델에서 시작한 실험은 정답률에 차이가 없었다. 그 실행에서 확신도의 변별력이 떨어졌지만 한 번의 실행에서 결과를 본 뒤 찾은 것이라 일반적인 말로 쓰지 않는다(§24). 쓸 수 있는 문장은 9.1c와 9.1e에 있다).
- "공개 dev 점수가 논문과 비슷하다/낮다" (학습에 없던 표만 골랐고, 근거 셀까지 채점하고, 모델이 다르다. 나란히 놓을 수 없다).
- "처음", "최초", "새로운 방법" (답과 근거의 불일치, 작은 모델의 셀 인용 강화학습, 근거 셀 보상과 그 위험은 이미 연구가 있다. AI 도구가 조사해 확인했다. §8 참고).
- "표 1,755개가 겹친다" (1,755는 페이지 수다. 셀까지 같은 표는 1,578개다).
- "검증기가 틀린 근거를 걸러 낸다" (답 텍스트가 표의 한 셀과 같으면 검증기는 근거를 그 셀로 고쳐서 답한다. 걸러 내는 것은 답과 셀이 안 맞는 경우다).
- "열 번호 형식으로 정답률을 올렸다" (줄어든 것은 근거 셀 오류다. 정답률은 그대로였고 검증기를 통과하는 오답은 늘었다. 300개 설정에서 한 번 실행한 결과이고 전체 데이터에서는 재지 않았다. `docs/REPORT.md` §19.7).
- "데모에서 EXAONE이 실시간으로 돈다" (공개 데모는 저장된 모델 출력을 재생한다. 그 자리에서 도는 것은 검증기와 도구와 휴리스틱 플래너다. 모델까지 도는 것은 로컬 실행뿐이다).
- "공고의 모든 항목을 같은 깊이로 구현했다" (원문에만 있던 gRPC, 챗봇, 메모리 결합, Personal Agent, 구조 이해 PLM은 2026-11-11에 좁은 범위로 더했다. 프로젝트의 중심은 여전히 테이블이해이고, 나머지는 "있다" 수준이다. §9 참고).

## 7. ko-search-clinic과 역할 나누기

지원자의 다른 공개 저장소 <https://github.com/sokldjs554/ko-search-clinic>도 한국어를 다루고 Kiwi 형태소 분석과 BM25를 쓴다. 두 저장소를 같은 이야기로 쓰면 "한국어 검색 프로젝트 두 개"로 읽힌다. 다음과 같이 나눠 쓴다.

## 8. 선행 연구 대비 주장 범위

**주장의 범위.** 답과 근거가 따로 맞고 틀리는 문제, 셀 인용 강화학습, 근거 셀 보상은 이미 연구가 있다. AI 도구가 가까운 논문을 원문으로 읽고 확인했다(`docs/research/papers.md`, `docs/REPORT.md` §19.4). 그래서 "처음", "새로운 방법"이라고 쓰지 않는다.

**논문 이름은 직접 읽은 것만 댄다(2026-11-16 결정).** AI 도구가 읽은 논문까지 이름을 대면 그 논문을 다시 읽어야 답할 수 있다. 그래서 서류, 포트폴리오, 면접에서는 아래 두 편만 "읽은 논문"으로 말한다. 면접에서 "이런 연구가 이미 있지 않나"라고 물으면 이렇게 답한다: "있습니다. 그래서 새로운 방법이라고 하지 않았고, 한국어 표에서 근거 셀 오류를 재고 규칙 검증기와 보류로 줄이는 폭을 수치로 보인 것이 이 프로젝트의 몫입니다." 특정 논문과의 차이를 물으면 "조사는 AI 도구로 했고 직접 읽은 것은 아니라서 자세히 말씀드리기 어렵다"고 그대로 말한다.

쓸 수 있는 문장: "한국어 표 질의응답에서, 답과 근거 셀을 함께 내는 작은 모델의 근거 오류를 정답 셀 기준으로 재고, 고정 규칙 검증기와 보류로 오답 유출을 줄이는 폭을 수치로 보였다."

**소유자가 직접 읽은 논문.** 소유자가 전에 읽었다고 알려 준 한양대 논문 두 편이다(2026-11-11, `docs/research/papers.md`의 "소유자가 읽은 한양대 논문 두 편"). 자기소개서나 면접에서 "읽은 논문"으로 말할 수 있는 것은 이 두 편뿐이다.

| 논문 | 한 것 | TableTrace와 이어 말할 곳 |
|---|---|---|
| 리즈닝 피드백 기반 학습(RFL), 한양대, 2025년도 한글 및 한국어 정보처리 & 한국코퍼스언어학회 공동 학술대회 | SFT한 모델이 틀린 학습 문항에 LLM 해설을 붙여 다시 학습. 대화 맥락 추론 정확도 93.72 → 95.04 | 모델의 오류를 학습으로 되돌린다는 뼈대가 같다. TableTrace는 그 신호를 LLM 해설이 아니라 규칙 검증에서 얻고, 검증기를 추론 때도 쓴다 |
| 한국어 LLM-as-a-Judge 루브릭 전략 비교, 한양대, 2026 한국컴퓨터종합학술대회 | 같은 judge라도 루브릭의 출처와 생성 절차에 따라 사람과의 일치가 48.57~68.55로 달라짐 | TableTrace가 채점과 검증을 규칙으로만 하는 이유의 배경. 동시에 서술형 답과 대화 품질은 규칙으로 못 잰다는 한계 |

**이전에 적어 둔 문장을 고쳤다(2026-11-15).** 대조군이 오기 전에는 이 자리에 "첫 실험이 효과가 없던 까닭이 학습 스크립트가 프롬프트를 자르는 결함으로 밝혀져"라고 적혀 있었다. 대조군 결과로 보면 틀린 말이다. 대조군은 프롬프트가 잘리지 않았는데도 첫 실험처럼 무너졌다. 프롬프트 잘림은 실제로 있던 결함이고 고쳤지만, 결과를 가른 것은 배치 구성이다. 그 문장을 이미 어딘가에 썼다면 위 문장으로 바꾼다.

**누가 무엇을 했는지.** 보상 함수와 GRPO 손실은 본인이 썼고, 다섯 번의 실행(첫 실험, 두 번째 실험과 그 반복, 대조군, 전체 데이터 모델에서 시작한 실험)은 본인이 GPU에서 돌렸다. 첫 실험의 기록에서 결함을 찾아 학습 스크립트를 고친 것, 대조군의 설계, 결과 분석은 AI 도구가 했다. 배치를 같은 수로 뽑게 한 것도 AI 도구가 쓴 스크립트의 설계였다. 그래서 "결함을 찾아 고쳤다", "대조군을 설계했다"의 주어를 본인으로 쓰지 않는다. "고쳐 다시 돌렸다", "대조군을 돌려 확인했다"로 쓰고, 물으면 역할을 그대로 말한다(0절).

### 9.2 구현하고 CPU에서 시험만 한 것 ("구현했다"까지만 쓴다)

- **모델이 도구를 고르는 에이전트(Tool Calling)**: 모델이 표 본문 없이 도구로 표를 읽고 제출한다. 대본대로 답하는 모의 서버로 테스트 6개. 실제 모델로는 CPU에서 튜닝하지 않은 EXAONE-4.0-1.2B로 수작업 30문항만 돌렸다: verified EM 16.7%(5/30, 전부 답 없는 질문의 보류), 같은 모델의 한 줄 답 방식 20.0%, 튜닝한 같은 크기 모델 66.7%. "경로가 실제 모델로 끝까지 돈다"까지만 쓴다. "도구 호출로 성능을 올렸다"는 틀린 말이다(`experiments/eval/tool_calling_cpu.json`).
- **본인이 직접 쓴 학습 코드**(2026-11-12, PR #6): 보상 함수, GRPO 이점·손실·KL 항, 라벨 가리기·학습률 일정·학습 루프. 전용 테스트 35개 통과. 리뷰에서 보상 함수를 저장된 모델 출력 66,450회 호출에 적용해 AI 도구의 임시 구현과 차이가 없음을 확인했다(`docs/rewrite/LOG.md`). "직접 구현했다"고 쓸 수 있다. 보상과 손실로 EXAONE을 학습한 결과는 9.1b, 9.1c, 9.1e에 있다. 학습 루프(`lm_loop.py`)로 학습한 결과는 9.1g에 있다(한 번). "직접 쓴 학습 루프로 EXAONE을 미세조정했다"고 쓸 수 있다. "모든 미세조정을 직접 쓴 루프로 했다"고는 쓰지 않는다.
- **큰 모델 참고선용 few-shot 평가, 엔진의 확신도 저장**: 평가 러너의 옵션으로 있고 모의 서버 테스트가 있다. (mT5의 확신도 저장은 실제로 돌렸다. 9.1 참고)

### 9.3 하지 못했거나 재지 못한 것 (쓰지 않는다)

- 2차 GPU 실험의 **문항별 예측**. 결과 파일이 세션과 함께 사라졌다. 그래서 그 실험들(32B, 데이터 확대, DDP, 열 번호 시드, 화학, 큰 표)의 대응 검정과 문항 단위 분석은 없다. 3차 실행의 것은 있다(9.1c). 화학은 다시 돌려 문항별 예측을 얻었다(9.1i).
- 세대와 양자화를 맞춘 크기 비교. 튜닝하지 않은 1.2B, 7.8B, 32B 세 점은 있다(9.1c). 다만 7.8B는 3.5 세대이고 32B는 다른 세션의 값이다.
- 강화학습의 시드를 바꾼 실행(본 실험은 시작 모델을 달리해 두 번, 대조군은 한 번 돌렸다), 프롬프트 수정만의 효과. 강화학습으로 계산·보류 문항이 나아진 결과. 전체 데이터 모델에서 시작한 강화학습의 반복(한 번 돌렸다, 9.1e). 모델이 틀리는 프롬프트만 골라 하는 강화학습, 확신도를 보는 보상.
- 직접 쓴 학습 루프와 스크립트의 루프를 같은 세션에서 나란히 돌린 비교(학습률 일정의 효과는 가르지 못했다). 직접 쓴 루프로 한 학습의 반복.
- 소유자가 쓴 30문항에서 전체 데이터 모델 둘과 튜닝하지 않은 두 크기 말고 다른 모델의 평가(가중치가 남아 있지 않다). 평가 문항의 여러 사람 검수. 화학 문항의 검수. 한국어만 튜닝한 모델의 화학 평가(화학 문항을 더한 몫을 가르려면 필요하다). 화학 재실행의 반복.
- bitsandbytes 4비트 서빙(그 vLLM 버전에 없는 방식). 풀 전부(약 3.4만 문항) 학습. 큰 모델의 튜닝. 도구 호출 형식으로 튜닝한 모델.
- 고친 32B 설정(메모리 90% 선점 등)은 GPU에서 확인되지 않았다. 표의 32B 결과는 고치기 전 설정이 두 번째 시도에서 통과한 것이다.
- **10,587문항 모델과 열 번호 형식 모델의 재학습.** 2026-11-15에 학습 스크립트의 길이 계산이 틀린 것을 찾았다(`docs/REPORT.md` §21.12). 그때까지의 모든 EXAONE 미세조정은 학습 예제의 15.0%에서 정답이 잘린 채 이루어졌다. 강화학습은 고친 설정으로 다시 했고(9.1c), 전체 데이터 모델도 고친 설정으로 다시 학습해 차이가 검출되지 않음을 확인했다(9.1d). 화학 모델은 2026-11-17에 고친 설정으로 다시 학습했다(9.1i). 나머지 모델(9.1b의 10,587문항, 열 번호)은 예전 설정으로 학습한 그대로다.
- **쓸 때 지킬 것**: EXAONE 튜닝 수치를 쓸 때 이 결함을 숨기지 않는다. "측정 뒤 학습 스크립트에서 정답이 잘리는 결함이 발견되어 고쳤고, 전체 데이터 모델을 고친 설정과 예전 설정으로 같은 세션에서 다시 학습해 견주니 정답률에 검출되는 차이는 없었다(86.4% 대 87.0%)"가 정확한 말이다.

### 9.4 면접에서 물으면

- "챗봇을 만들었나" → 한 건짜리 검증 파이프라인 위에 세션 기억과 사용자 기억을 얹고, 후속 질문을 규칙 세 가지로 완성하게 했다. 언어모델이 대화를 관리하지 않게 한 이유는 무엇을 채웠는지 설명할 수 있어야 해서다. 평가의 후속 질문은 틀로 만든 것이라 자연 대화 성능은 모른다.
- "Tool Calling은" → 구현하고 모의 서버로 검증한 뒤, 튜닝하지 않은 EXAONE으로 쟀다고 말한다. 1.2B는 셀을 한 번 찾아보고 대부분 보류해서 14.0%였고(CPU 30문항에서도 16.7%로 같은 모습), 32B는 51.5%였다. 같은 32B에게 표를 보여 주고 프로그램 한 줄을 쓰게 하면 74.5%라서, 이 크기의 표에서는 도구 호출이 불리했다. 같은 1.2B에게 프로그램 한 줄을 쓰게 하면 27.0%라서(도구 호출 14.6%, 대응 검정 p <0.001) 작은 모델에서도 같았다. 도구 호출 형식으로 튜닝하는 것이 다음 단계다.
- "큰 표는" → 처음에는 작은 모델의 입력 길이 때문에 뺐고, 나중에 행 선별을 넣어 공개 dev의 처음 보는 표 3,072문항으로 쟀다. mT5는 37.8%로 낮았고, 튜닝한 EXAONE 1.2B는 앞에서부터 자르면 72.6%, 질문과 겹치는 행을 고르면 85.2%였다.
- "화학 논문은" → 평가용 표 20개를 공개 라이선스 논문에서 뽑았다. 학습은 교과서 표다. 특허는 없다. 한국어와 화학을 함께 튜닝한 EXAONE 1.2B가 논문 표 62문항에서 74.2%였다(튜닝하지 않은 같은 모델 24.2%, 휴리스틱 43.5%). 처음 돌렸을 때는 80.7%였는데 그 실행은 결과 파일이 남지 않았고, 문항별 예측을 남기려고 다시 돌린 결과가 74.2%다. 낮은 쪽이지만 파일이 있는 쪽을 쓴다고 말한다. 계산 문항이 약하고 본문 문항은 못 푼다.
- "강화학습은 어떻게 됐나" → 숨기지 말고 순서대로 말한다. (1) 보상 함수와 GRPO 손실을 직접 구현해 EXAONE 1.2B에 200걸음 적용했다. 목표는 답은 맞는데 인용 셀이 틀리는 오류를 줄이는 것이었다. (2) 첫 실험은 줄지 않았다. 개발셋 보상은 25걸음에서 가장 높았고 그 뒤로는 모델이 답을 덜 냈다. (3) 기록을 따라가니 학습 스크립트에 문제가 둘 있었다. 긴 프롬프트의 앞부분이 잘렸고(학습 프롬프트의 12.2%), 배치를 조회·계산·보류 질문에서 같은 수로 뽑아 보류 질문이 실제 비율의 네다섯 배로 나왔다. 둘 다 AI 도구가 쓴 스크립트의 문제였고, AI 도구가 분석하다 찾아 고쳤다. 직접 쓴 보상·손실 함수의 문제가 아니었다. (4) 둘을 고쳐 다시 돌린 두 번째 실험에서 인용 셀 정확도가 26.2% → 43.8%, verified EM이 55.2% → 59.4%가 됐다(같은 699문항에서 50 대 21, p <0.001). 보상은 정답 셀 표시를 쓰지 않는다. 복구 없이 통과한 정답에 1.0점, 검증기가 근거를 고쳐야 했던 정답에 0.3점을 주는 차이만으로 움직였다. (5) 둘 가운데 무엇이 효과를 냈는지 가르려고 배치 구성만 되돌린 대조군을 돌렸다. 대조군은 프롬프트가 온전했는데도 첫 실험처럼 무너졌다. 인용 셀 정확도는 25.7% → 26.5%로 그대로였고, 학습 마지막 50걸음의 표본 1,600개 가운데 1,579개가 검증되지 않는 답이었다. 그러니 효과의 조건은 배치를 실제 문항 비율로 뽑는 것이었다. 까닭은 이렇게 본다. 300문항 모델은 계산 프로그램과 보류를 쓸 줄 모른다. 그런 질문에서는 검증되지 않는 답을 써서 0점을 받는 것이 최선이고, 그런 질문이 배치의 3분의 2를 차지하면 그 버릇이 조회 질문까지 번진다. (6) 결과가 한 번뿐이라 본 실험을 한 번 더 돌렸다. 대조군과 같은 시작 모델에서 돌았고 같은 결과였다(인용 셀 정확도 25.7% → 46.7%). 같은 가중치에서 시작한 대조군과는 표본 추출만 다른데 근거 셀에서 갈렸다(p <0.001). (7) 한계도 같이 말한다. 본 실험은 두 번, 대조군은 한 번이고 강화학습의 시드는 바꾸지 않았다. verified EM은 대조군과 유의하게 다르지 않다(p 0.119). 유의하게 다른 것은 근거 셀이다. 계산 문항은 풀게 된 것이 아니라 틀린 답이 보류로 바뀌었다. 전체 데이터 미세조정(84.3%)이 훨씬 높고 빠르다. (8) 그래서 전체 데이터로 미세조정한 모델에서 같은 강화학습을 한 번 더 돌렸다. 정답률은 그대로였다(86.0%와 86.1%, 8 대 7). 표본의 87.6%가 이미 정답이라 배울 신호가 드물었다. 실행 전에 그렇게 예상해 적어 두었다. 예상하지 못한 것도 있었다. 정답률은 같은데 모델의 확신도가 맞은 답과 틀린 답을 덜 갈랐다(AUROC 0.757에서 0.69). 한 번의 실행이고 결과를 본 뒤에 찾은 것이라 확인이 더 필요하다고 말한다. **"결과가 이상할 때 기록을 따라가 원인 후보를 세우고, 고친 뒤 대조군으로 어느 것이 원인인지 가렸다"는 과정 자체가 말할 거리다. 본인이 한 일은 보상·손실 구현과 다섯 번의 실행이라고 나눠 말한다.**
- "큰 모델은 써 봤나" → EXAONE 32B(4비트 AWQ)를 T4 두 장에 텐서 병렬로 올려 같은 검증기로 쟀다. 튜닝 없이 예시 6개만 주면 77.2%로, 3,588문항으로 튜닝한 1.2B(84.3%)보다 낮았다. 큰 모델도 답은 맞고 근거 셀이 틀리는 일이 15.6% 있었다. 튜닝은 하지 않았다. 같은 방식으로 1.2B는 27.0%, 7.8B는 49.8%였다. 튜닝 없이는 클수록 높았지만 셋 다 튜닝한 1.2B보다 낮았다. 7.8B는 3.5 세대라 크기만의 비교는 아니다.
- "결과 파일이 없다던데" → 사실대로 말한다. Kaggle 세션이 바뀌며 결과 파일이 사라졌고, 노트북에 남은 출력에서 지표를 복원했다. 그래서 문항별 분석은 없다. 그 뒤로는 결과를 절마다 GitHub 브랜치로 올리게 고쳤다. 세 번째 실행(2026-11-15)부터는 결과 파일을 받았고, 받을 때마다 저장된 출력을 이 저장소의 검증기로 다시 검증해 판정이 모두 같음을 확인했다.
- "학습 스크립트에 결함이 있었다던데" → 숨기지 않는다. 길이 한도 계산이 틀려 학습 예제의 15.0%에서 정답이 잘렸다. AI 도구가 쓴 스크립트의 결함이고 AI 도구가 분석하다 찾았다. 고친 뒤 전체 데이터 모델을 고친 설정과 예전 설정으로 같은 세션에서 다시 학습해 견줬다. 정답률에 검출되는 차이는 없었다(86.4% 대 87.0%, 같은 문항에서 23 대 27). 정답이 잘리던 길이의 문항만 봐도 같았다. 그 과정에서 학습을 다시 하는 것만으로 정답률이 2.9%p 움직인다는 것도 드러났다(예전 설정 세 번: 84.3%, 87.1%, 87.0%). 그래서 대표 수치로는 가장 낮은 1회째를 쓴다.
- "학습 코드를 직접 짰나" → 범위를 나눠 말한다. 직접 쓴 것은 보상 함수, GRPO의 이점과 손실, 미세조정 학습 루프다(133줄). 명세와 테스트는 AI 도구가 썼고 그것을 보고 구현했다. 실제 학습에 쓰인 것도 나눠 말한다. 보상과 손실은 EXAONE 강화학습 다섯 번에 쓰였다. 학습 루프로는 전체 데이터 미세조정을 한 번 했고 test 86.0%가 나왔다(9.1g). 대표 수치의 모델과 다른 실험의 모델들은 AI 도구가 쓴 스크립트의 루프로 학습됐다. 내 루프가 스크립트의 루프와 다른 점도 말할 수 있어야 한다: 학습률을 선형으로 줄인다. 설명할 수 있어야 하는 것: 보상을 다섯 단계로 나눈 이유(답 없는 질문에서 검증기가 거부한 출력에 점수를 주지 않는다), 그룹 안에서 이점을 정규화하는 이유, 로그 확률을 한 칸 어긋나게 읽는 이유, 손실을 누적 횟수로 나누는 이유, 검증기 예외를 보류로 처리한 이유.
- "어떤 논문을 읽었나" → 한양대 두 편만 말한다(8절). 관련 연구 조사에 AI 도구를 썼다는 것은 물으면 그대로 말하되, AI 도구가 읽은 논문의 이름은 먼저 꺼내지 않는다. RFL은 "틀린 문항을 골라 다시 가르친다"는 점에서 이 프로젝트의 강화학습과 이어지고, 루브릭 논문은 "LLM 판정은 설정에 민감하다"는 점에서 규칙 검증기를 고른 이유와 이어진다. 두 논문의 수치를 말할 때는 원문의 표를 다시 보고 말한다.

## 10. 지원 전 마지막 대조 (2026-11-16)

공고 페이지를 다시 받아 대조했다. 본문은 2026-11-10의 기록과 같다. 문구와 항목별 표는 `docs/research/job-posting.md`에 있다.

### 10.0 실험이 모두 끝난 뒤 다시 대조하며 찾은 것 (2026-11-16 저녁)

9.1e와 9.1f의 결과를 넣은 뒤 문서 전체를 공고의 항목과 한 번 더 대조했다. 공고 본문은 같은 날 오전에 다시 받아 확인한 그대로다. 자세한 것은 `docs/REPORT.md` §26.

1. **직접 쓴 학습 루프는 그때까지 GPU 학습에 쓰인 적이 없었다(같은 날 저녁에 한 번 돌려 메웠다, 9.1g).** 지금까지의 문서는 "이 코드로 EXAONE을 학습한 결과가 있다"고만 적어서 세 파일이 모두 쓰인 것처럼 읽혔다. 쓰인 것은 보상과 손실이다. 저장된 EXAONE 미세조정의 학습 기록은 모두 `"loop": "builtin"`이거나 그 옵션이 생기기 전의 것이고, 노트북은 `--loop owner`를 준 적이 없다. 문서를 고쳤다. 공고의 "한국어 언어 모델 튜닝"에 가장 직접 닿는 항목이라, 메우려면 노트북 2의 M절을 돌린다(10.4). **같은 날 저녁에 돌렸다(9.1g).** 직접 쓴 루프로 한 전체 데이터 미세조정이 test 86.0%로, 스크립트의 루프로 한 여섯 번의 범위 안이다. 이제 비어 있는 것은 "그 한 번 말고 다른 모델들은 스크립트의 루프로 학습됐다"는 것이다.
2. **한 장 요약(`docs/ONE_PAGE.md`)이 낡아 있었다.** 전체 데이터 학습을 네 번으로, GPU 실행을 2026-11-15까지로 적고 있었고 직접 쓴 문항의 결과가 없었다. 포트폴리오의 바탕이 되는 문서라 고쳤다.
3. **화학 문항도 기준선과 같은 낱말을 쓴다.** 9.1f에서 본 것(AI 도구가 쓴 계산 문항이 휴리스틱에 유리했다)을 다른 세트에서도 세었다. 질문의 낱말만으로 휴리스틱이 맞는 연산을 고르는 계산 문항이 화학 교과서 문항 7/7, 화학 논문 문항 12/19다. 다만 그 문항들에서 휴리스틱의 정답은 2/7, 4/19라서 기준선이 덕을 봤다는 증거는 없다. 화학 문항은 여전히 검수되지 않았다.
4. 그 밖에 틀린 수치나 서로 어긋나는 서술은 찾지 못했다. 수치는 산출물과 자동으로 대조된다(3,700여 개).

### 10.1 공고에서 새로 확인한 것

- **목록에 보이는 요약에는 묶음이 넷뿐이다**: 초거대 언어모델 / 심층문서이해 / 강화학습 / LLM 기반 AI서비스·Agent. **테이블이해(Table MRC)는 본문의 수행 업무에는 있고 요약에는 없다.** 까닭은 알 수 없고 추정하지 않는다. 다만 지원서를 테이블이해 하나에만 기대어 쓰지 않는다. 첫 문단에서 "한국어 표 질의응답의 근거 검증"을 말하되, 같은 문단에 요약의 묶음 이름으로 읽히는 것을 함께 둔다: 한국어 언어모델 튜닝과 서빙(EXAONE LoRA, vLLM), 강화학습(직접 쓴 보상과 손실, 대조군까지 돌린 실험).

### 10.2 묶음별로 근거가 충분한 것과 약한 것

| 묶음 | 근거가 충분한 것 | 약한 것 (물으면 그대로 말한다) |
|---|---|---|

### 10.3 저장소로는 채울 수 없는 것 (가장 중요하다)

1. **직접 쓴 코드의 범위.** `src/` 5,145줄 가운데 본인이 쓴 것은 637줄(12%)이다: 숫자·단위 파서, 계산기, 프로그램 문법, 셀 도구, 검증기, 보상 함수, GRPO 손실, 학습 루프. 나머지 소스와 스크립트·테스트·문서는 AI 도구가 썼다. 그 637줄 가운데 학습 루프(68줄)는 전체 데이터 미세조정 한 번에 쓰였다(9.1g). 코드 밖에서 직접 한 것은 평가 문항 30개와 기존 30문항의 검수, 그리고 모든 GPU 실행이다. 서류와 면접에서 이 범위를 그대로 말한다(§0). 면접 전에 이 여덟 파일을 다시 읽고, 한 줄씩 왜 그렇게 썼는지 말로 설명해 본다. 9.4의 질문 목록이 그 연습이다.
2. **코딩테스트.** 공고의 필요역량 "python 코딩 중급 이상"은 저장소가 아니라 Codility 시험과 면접에서 가려진다.
3. **논문.** 공고의 필요역량에 "최신 딥러닝 논문 독해"가 있다. 서류와 면접에서는 직접 읽은 한양대 두 편만 말한다(§0의 6, §8). 면접 전에 그 두 편의 방법과 수치를 다시 본다. 시간이 남으면 KorWikiTQ 원논문(이 프로젝트의 데이터, 7쪽) 하나를 읽어 두면 "데이터에 대해 아느냐"는 질문에 답하기 쉽다. 선택이다.
4. **기본기.** "LLM 동작 원리", "네트워크 및 서버 구조"는 프로젝트 산출물로 증명되지 않는다. 이 프로젝트에서 실제로 쓴 것(LoRA가 무엇을 학습하는지, 토큰 로그 확률, vLLM이 요청을 묶어 처리하는 방식, REST와 gRPC의 차이, 비동기 작업 큐)을 자기 말로 설명할 수 있게 한다.
