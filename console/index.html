TableTrace는 답만 내놓지 않습니다. 질문을 받으면 관련 본문과 표를 검색하고, 모델이 어느 셀·어느 문장·어떤 계산으로 답하는지 제안하면, 제한된 도구가 그 계산을 다시 실행해 검증합니다. 근거가 부족하면 답변을 보류하고 이유를 보여 줍니다.
  1. 1 문서·표 선택
  2. 2 질문 입력 또는 대표 질문 선택
  3. 3 검색 · 모델 제안 · 도구 실행
  4. 4 답변과 근거 셀·문장·계산식 검토
저장된 실행 결과를 보고 있습니다. 백엔드가 없으므로 새 질문은 실행되지 않고, 대표 질문의 기록된 결과만 열 수 있습니다.

    대표 질문

    문서를 고르면 그 문서의 대표 질문이 나옵니다.

    왼쪽에서 문서를 고르세요

    한국어 표는 KorWikiTQ(위키백과 표+설명), 영어 화학 문서는 OpenStax Chemistry 2e의 본문과 실험 데이터 표입니다. 표의 각 셀에는 r행c열 좌표가 있어 답변의 근거를 정확히 가리킬 수 있습니다.

    질문

    결과가 여기에 표시됩니다: 답변 · 근거 셀/문장 · 계산식 · 검증 항목 · 실행 추적.

    작동 방식

    질문은 LangGraph로 짜인 그래프를 지납니다: retrieve(BM25로 표·문단 검색) → propose(모델이 op / cells / answer 프로그램을 제안. 모델은 CPU에서 도는 mT5-small이거나 vLLM·SGLang 서버의 EXAONE-4.0-1.2B LoRA이고, 모델이 없으면 어휘 겹침 휴리스틱) → tool(셀 조회·제한 산술 계산) → verify(셀 범위·답-셀 일치·재계산·단위·기간 검사) → 답변 또는 보류. 모델 출력이 해석되지 않거나 검증에 실패하면 휴리스틱으로 한 번 더 제안합니다.

    
      
    신뢰 경계
    
      
      
        
    • 문서 본문·셀·질문은 데이터입니다. 어떤 문자열도 명령으로 해석되지 않고, 계산기는 숫자·사칙연산·괄호만 받는 AST 평가기입니다. 임의 코드 실행은 없습니다.
      • 
        
    • 모델이 낸 셀 좌표는 표 범위를 검사하고, 답은 그 셀의 텍스트와 비교합니다. 인용한 셀에 답이 없으면, 답과 같은 셀이 표에 하나뿐일 때만 근거를 그 셀로 고치고 그 사실을 실패한 검사로 남깁니다. 그렇지 않으면 검증 실패로 보류합니다. 표에는 근거가 된 셀과 모델이 인용했지만 근거가 되지 못한 셀(점선, "모델" 표시)이 따로 나옵니다.
      • 
        
    • 계산은 모델의 숫자가 아니라 도구가 다시 계산한 값을 씁니다. 단위가 다른 셀끼리는 계산을 거부합니다.
      • 
      
    
      
    실시간 실행과 저장된 결과
    
      
    백엔드(FastAPI)가 연결되면 모든 질문이 실제로 실행되고 결과에 실시간 실행이 붙습니다. 공개 데모(GitHub Pages)는 정적 파일만 제공하므로 저장소의 모델로 미리 실행해 둔 결과를 저장된 실행 결과로 보여 주며, 기록 시각·모델·커밋을 함께 표시합니다. 로컬에서 docker compose up으로 띄우면 같은 화면이 실시간으로 동작합니다.
